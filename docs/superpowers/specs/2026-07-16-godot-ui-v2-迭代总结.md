## 一、项目背景

BattleBlitz 是一款 Fire Emblem / Advance Wars 风格的战棋游戏。原本只有 **Python 后端 + JS Web 前端**,V2 阶段的任务是把前端**移植到 Godot 4.7 原生客户端**,同时**重新设计整套 UI**,目标是:

- **风格基调**:老 GBA《火焰之纹章》(FE6/7/8)+ 高战金属感
- **布局**:棋盘为主紧凑,左 30% 信息区,4 角极小 HUD pill
- **交互**:鼠标点击 + 浮层 HUD + 行动气泡 + 战报面板
- **后端**:Python FastAPI + WebSocket,本次 V2 阶段保持不变

## 四、真实 WS 接入(`820205c`)

V2 收官后,把 mock 数据换成真实后端,跑通完整流程。

### 数据流

```
Godot                  FastAPI (127.0.0.1:8000)
  │                          │
  ├─ POST /games ──────────► │  201 Created
  ├─ POST /games/8/join ───► │  201 Created (player_id=8)
  ├─ POST /games/8/add-ai ─► │  201 Created (AI player_id=9)
  ├─ POST /games/8/start ──► │  200 OK
  │                          │
  ├─ WS connect ───────────► │
  │                          │  server.hello
  │ ◄── state.snapshot ──────┤  (2 players, 225 tiles)
  │                          │
  ▼                          ▼
  HUD 更新                  后端继续推
  棋盘渲染                  event.delta
  InfoPanel 填充
```

### 抓到 4 个集成 bug

| # | 位置 | Bug | 修复 |
|---|---|---|---|
| 1 | main.gd `api_response` | POST /games 返回 **201**(Created)但代码只接 200 | 接受 200 + 201 |
| 2 | main.gd `_on_join_game_response` | 后端 join 响应是 Player dict 直接(`{id:N,user_name:...}`),代码找 `player_id`/`player.id` 找不到 | 优先 `body.id` |
| 3 | main.gd `_snapshot_to_pseudo_map` | 后端 tile.subtype 是 `null` 不是 `""`,`String(null)` 崩 | Variant + null 检查 + `str()` |
| 4 | network_client.gd `request` | HTTPRequest **单连接 race** — add-ai 和 start_game 并发发会丢 `pending_*` meta | 加 `_req_busy + _req_queue` 串行化 |
