## 0. 架构总览

BattleBlitz 是一套 **后端 + 双前端** 的回合制战棋游戏（Fire Emblem / Advance Wars 风格）。

```
┌──────────────────────────────────────────────────────────────┐
│  客户端                                                       │
│  ┌──────────────────┐        ┌────────────────────────────┐  │
│  │ Godot 4.7 客户端 │ 主体验  │ 遗留 Web UI（原生 JS）      │  │
│  │ 42 .gd / 20,398 行│        │ app.js，冻结维护            │  │
│  └────────┬─────────┘        └──────────────┬─────────────┘  │
│           │ HTTP + WebSocket               │ HTTP 轮询      │
└───────────┼─────────────────────────────────┼───────────────┘
            │                                 │
┌───────────▼─────────────────────────────────▼───────────────┐
│  后端 FastAPI（game/app/，145 文件 / 31,718 行）               │
│                                                               │
│  routes/ (19 文件 8,104 行, 74 端点)  ← HTTP/WS 接入层         │
│      ↓                                                        │
│  game_logic.py + movement.py     ← 规则引擎（战斗/回合/经济）   │
│      ↓                                                        │
│  classes/  progression/  commanders/  hero_domain/            │
│  mainline/  map_generation/  status/  save/  agent/           │
│      ↓                                                        │
│  models.py + database.py  ← SQLAlchemy 2.0 async / aiosqlite  │
│      ↓                                                        │
│  battleblitz.db (SQLite)                                       │
└───────────────────────────────────────────────────────────────┘
```

**关键分层原则**：
- **兵种 / 技能 / 英雄全部数据驱动** —— 新增一个兵种只需新建一个 `.py` 文件，注册表自动发现，**不改 config、不改 game_logic**。
- **规则只在后端** —— 客户端只做渲染与输入，服务端实时校验权限与合法性。
- **全量状态快照** —— `GET /state` 返回完整状态，避免 N+1 请求。

**接口示例**（`units/swordsman.py`）：
```python

    type_id = "swordsman"
    display_cn = "剑士"
    glyph = "剑"
    base_hp, base_atk, base_def, base_mov = 45, 18, 12, 5

    default_skills = []
    attack_range = 1
```

`app/classes/units/skills/`，继承 `BaseSkill`：

| 技能 | `skill_id` | 性质 | 说明 |
|---|---|---|---|
| 狙击 | `snipe` | 被动 | 修改攻击射程 |
| 连击 | `double_strike` | 被动 | 修改攻击伤害（双击 50%）|
| 治愈 | `heal` | 主动 | 相邻友军回血 |

### 3.3 英雄（6 个）

`app/classes/heroes/` —— 继承 `BaseHero` 或 `CommanderPassive`（云 / 安娜 / 鸢影 带被动）。

**云 `yun` / 安娜 `anna` / 白予 `baiyu` / 林依澜 `lin_yilan` / 洋子 `youko` / 鸢影 `yuanying`**

每个英雄一套三件套美术资源：`heroes/<id>.png`（棋盘 Q 版 sprite）、`portrait_<id>.png`（对话立绘）、`crest_<id>.png`（纹章头像）。

> 英雄与兵种的绑定关系：英雄仍用 `unit_type`（基础兵种）参与战斗，`hero_id` 只驱动名字、美术和设计者烘焙的属性覆盖。

### 3.4 新增一个兵种的完整流程

1. 新建 `game/app/classes/units/assassin.py`
2. `class Assassin(BaseUnitClass)`，实现全部 abstract 属性
3. **注册表自动发现，重启即生效** —— 不改 `config.py`、不改 `game_logic.py`

## 四、核心数据模型

### ER 关系

```
Game (1) ──< (N) Player ──< (N) Unit
  │              │
  │              └──< (N) ClaimSession   （建筑占领会话）
  ├──< (N) Tile                        （棋盘格）
  └──< (N) ActionLog                    （战报）
  
PlayerProfile (1) ──< (N) UnitInstance  （养成档案）
                            ├──< EquipmentTemplate
                            └──< TalentDefinition
MatchRecord                                  （战绩）
GameSaveSlot / SuspendState                  （存档 / 挂起）
```

**13 张表**：`games` / `players` / `units` / `tiles` / `claim_sessions` / `action_logs` / `player_profiles` / `unit_instances` / `equipment_templates` / `talent_definitions` / `match_records` / `game_save_slots` / `suspend_states`

### 4.1 `units` 关键字段

| 字段 | 说明 |
|---|---|
| `unit_type` | 兵种 `type_id`（16 种之一）|
| `hero_id` | 英雄绑定；普通单位为 NULL |
| `hp` / `max_hp` / `atk` / `def_` | 物理属性（`def_` 用下划线避开 Python 关键字）|
| `matk` / `mdef` | 魔法属性 |
| `mov` | 移动力上限 |
| `mp` | **本回合剩余 MP**，回合开始重置为 `mov` |
| `morale` | 士气 0–3，击杀 +1，永久保留 |
| `has_moved` / `has_acted` | 分离：可先移动再攻击 |
| `status_effects` | JSON 数组，存 5 种异常状态（`poison`/`paralyze`/`blind`/`slow`/`silence`）|
| `growth_seed` | 成长随机种子 —— **保证存读档后 L10 数值一致** |
| `campaign_base_stats` | 装备等临时加成前的裸属性，用于主线永久成长结算 |
| `skills` | JSON 数组，如 `["snipe"]` |

> `level` / `exp` 是**遗留字段**（`level` 恒为 1，`exp` 未使用），成长已改为士气制，保留仅为数据库兼容。

### 4.2 `players` 关键字段

| 字段 | 说明 |
|---|---|
| `seat` | 回合顺序；座位 0 享首回合 1 行动限制 |
| `team_id` | 队伍分组；同一 `team_id` 视为一个逻辑阵营参与胜负判定，NULL 时回退 `color` |
| `co_state` | JSON，指挥官 CO 能量状态 |
| `gold` | 本局金币，来自建筑收入，用于招募 |
| `is_spectator` | 观战者：不给单位、不参与胜负判定、**但占一个回合位**（防止战局跑飞）|

唯一约束：`(game_id, user_name)` / `(game_id, color)` / `(game_id, seat)`

## 五、规则引擎

### 5.1 伤害公式

```
有效攻击 = X × (1 + 攻击方士气 × 0.10)          # X = ATK 或 MATK，由「攻击方」attack_kind 决定
有效防御 = (Y + 地形加成) × (1 + 防守方士气 × 0.05)  # Y = DEF 或 MDEF
伤害    = 有效攻击 × (有效攻击 / (有效攻击 + 有效防御)) × 兵种克制 × 暴击
```

- **暴击**：基础 5% + 每级 1%，伤害 ×1.5
- **兵种克制**：`strong_against` 声明的边 ×1.20（**倍率硬编码在 `classes/units/__init__.py`，不在 config.py**）
- **最低伤害**：1

### 5.2 两条克制线

1. **属性线（物理 ⇄ 魔法）** —— 靠数值天生形成，无需配置。物打魔高伤、魔打物高伤、同系中伤。
2. **克制线（`strong_against` 显式声明）** —— 7 条边，见 §3.1。

### 5.3 反击

被攻击方存活且射程够得到攻击者时自动反击，伤害 ×0.5（`COUNTER_DAMAGE_MULT`），**伤害类型跟随反击方自己的 `attack_kind`**。AI 攻击路径与玩家攻击路径共用同一反击分支，避免规则漂移。

### 5.4 异常状态

`app/status/engine.py` 集中实现，存于 `Unit.status_effects` JSON：

| 状态 | 图标 | 默认持续 | 效果 |
|---|---|---:|---|
| `poison` 毒 | ☠ | 3 | 每回合 5% 最大 HP |
| `paralyze` 麻痹 | ⚡ | 2 | 25% 概率无法行动 |
| `blind` 致盲 | ◌ | 2 | 50% 概率无法行动 |
| `slow` 减速 | ❄ | 2 | 移动力 ×0.5 |
| `silence` 沉默 | 🔇 | 1 | 无法用技能 |

### 5.5 地形（`TERRAIN_MOVE_COST` / `TERRAIN_DEF_BONUS`）

> ⚠️ **MP 是双倍制**（平地 2、道路 1、山地 6）。旧文档的 1/2/3 已作废。

| 地形 | MP | 防御 | 说明 |
|---|---:|---:|---|
| 道路 / 桥 | 1 | 0 | MP 减半 |
| 平地 | 2 | 0 | — |
| 沙地 | 3 | 0 | 比平原慢，比山快 |
| 森林 | 4 | +2 | 阻挡远程视线 |
| 山地 / 雪峰 | 6 | +3 | 阻挡远程视线 |
| 河流 | 6 | 0 | 阻挡视线；需绕行或走桥 |
| 村庄 | 2 | 0 | 每回合 50 金 |
| 兵营 | 2 | +1 | 每回合 100 金；可招募 |
| 城堡 | 2 | +5 | 占满即胜（`seize`）|
| 关卡 | 不可通行 | 0 | 敌方阻拦 |
| 城堡地板/阶梯/宝库/门 | 2 | 3/3/5/3 | — |
| 王座 | 2 | +6 | 最安全 |
| 城墙 | 不可通行 | — | 阻挡格 |

### 5.6 胜利条件（`Game.win_condition`）

| 值 | 判定 |
|---|---|
| `rout`（默认）| 歼灭对手全部单位 |
| `seize` | 占领敌方 HQ |
| `reach` | 任意单位抵达 `reach_tile_id` |
| `defend` | 坚守 `defend_turns` 回合 |

### 5.7 回合流程与公平性

- 每回合行动预算 `_actions_per_turn()`：**座位 0 首回合 1 个，之后所有人每回合 2 个**
- 首次玩家结束回合后置 `first_player_done_first_turn = True` 锁定
- 每单位每回合只能移动一次，移动后仍可攻击（`has_moved` / `has_acted` 分离）
- 全员结束 → `apply_end_of_turn()`：建筑收入结算 → 异常状态扣血 → 清理死单位 → 胜利检查 → `turn_number += 1` → 重置 MP 与 `has_acted`
- **建筑占领**：`ClaimSession` 需持续 2 回合；期间占领者阵亡或离开会取消，**到期前不改 `Tile.owner_id`**

### 5.8 AI

- 规则引擎为主（`game_logic.py`），LLM 为可选增强（`agent/`）
- 优先级：治疗 → 攻击（低血优先）→ 移动（靠近敌人 / 占城 / 利用地形）→ 待命
- `AI_THINK_DELAY_SECONDS = 1.2`（人眼友好）、`AI_MAX_ACTIONS_PER_TURN = 5`（防死循环）、`AI_AGGRO_RANGE = 4`
- AI 链在独立 asyncio Task 中链式执行，不阻塞 HTTP 请求

`routes/mainline/prepare.py` 提供：佣兵配置 → 装备 → 转职 → 完成准备。
配合商店（`shop.py`）与佣兵分配（`mercenary.py`）构成 FE8 式战前整备。

项目采用**双轨制单位模型**（规范见 [`docs/规范/双轨制单位模型设计方案.md`](../规范/双轨制单位模型设计方案.md)）：

## 九、事件总线与 WebSocket

### 9.1 事件总线（`app/events/`）

进程内 pub/sub，按 `game_id` 分区，`asyncio.Queue` 每订阅者一个队列，慢订阅者不反压发布者。

**20 种事件类型**：

| 分类 | 事件 |
|---|---|
| 行动 | `move` `attack` `kill` `skill` `wait` |
| 占领 | `claim_start` `claim_complete` |
| 指挥官 | `commander_changed` |
| 回合 | `turn_end` `round_end` `match_start` `match_end` |
| 战略 | `castle_captured` `level_up` `low_hp_warning` `comeback` `victory_imminent` |
| 系统 | `ai_step` `auto_skip` `error` |

`GameEvent` 带 `importance` 属性（`CRITICAL_EVENTS` / `IMPORTANT_EVENTS` / normal），供解说与 UI 分级使用。

### 9.2 生产 WebSocket 网关 ★

> **旧文档说"生产 WS 网关待接入"—— 这个结论已过期。** 网关已上线且 Godot 客户端已在使用。

- 端点：`ws://<host>/ws/games/{game_id}?player_id={pid}&since_seq={N}`
- 实现在 `routes/ws_gateway.py`，前缀 `/ws`
- **认证**：`player_id` 走 query param（浏览器 WebSocket 无法设自定义 header）
- **断线续传**：`since_seq` 序号游标 + `_remember_event()` 环形记忆，重连不丢事件
- **心跳**：服务端 `_heartbeat()` + 客户端 `network_client.gd` 双 Timer
- **自动重连**：客户端 `_schedule_reconnect()`
- **断线兜底**：连接断开时触发 `_capture_disconnect_suspend()` 自动挂起对局

> ⚠️ `test_ws_gateway.py` 有 19 个用例在 Windows 上因 starlette TestClient + aiosqlite 线程泄漏而 skip，属环境限制而非功能缺失。

### 9.3 协议 v1（`app/protocol/v1.py`）

`PROTOCOL_VERSION = 1`

| 帧 | 方向 | Payload 模型 |
|---|---|---|
| `server.hello` | S→C | `ServerHelloPayload` |
| `event.delta` | S→C | `EventDeltaPayload` |
| `turn.advance` | S→C | `TurnAdvancePayload` |
| `action.move` | C→S | `ActionMovePayload` |
| `action.attack` | C→S | `ActionAttackPayload` |
| `action.skill` | C→S | `ActionSkillPayload` |
| `error` | S→C | `ErrorPayload` + `ErrorCode` |

### 10.2 棋盘渲染要点

- **48px 棋子 sprite**，`filter=nearest` 保证小尺寸清晰

- 棋子右上：**士气星**（★☆☆，0–3 星）

## 十二、API 设计原则

- **RESTful 风格**：资源在 URL，动作通过 HTTP 方法表达
- **全量状态返回**：`GET /games/{id}/state` 返回完整快照，避免 N+1
- **操作即验证**：每次 move/attack 实时校验权限与合法性，不留"校验队列"
- **player_id 双重校验**：请求体与路由逻辑交叉验证，防伪造
- **中文错误消息**：面向中文玩家
- **可发现**：全部 74 个端点自动注册到 `/docs` OpenAPI
