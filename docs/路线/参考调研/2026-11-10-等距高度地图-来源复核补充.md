## 1. 目标结构

```text
方格战棋地图
├── 逻辑地图：格坐标、地形类型、每格高度
│   └── 规则：四邻接移动、爬升/跳落限制、射程与视线
└── 表现地图（读取逻辑地图）
    ├── 投影与相机：把方格显示为菱形
    ├── 地表顶面与悬崖侧面
    ├── 单位脚底锚点与遮挡
    └── 点击选格、移动范围和路径高亮
```

这是职责与调用关系，不要求建立类继承。截图只能证明外观，无法判断原游戏使用纯 2D 还是 3D。常见 2:1 菱形也不等于镜头俯角 45°：3D 相机水平转向可取 45°，俯角需按目标画面另定。

## 2. 已核实参考项目

| 来源 | 确认内容 | 用途与边界 |

| [ramaureirac/godot-tactical-rpg](https://github.com/ramaureirac/godot-tactical-rpg) | MIT；README 标明 Godot 4.3，回合、走格、攻击、镜头旋转和 Blender 地图导入 | 3D 战棋整合参考；作者明确只是简单模板；高差规则与当前 Godot 的兼容性尚未实跑确认 |

原型素材：[Cozy Console 等距原型包](https://cozyconsoleco.itch.io/32-x-32-isometric-prototyping-kit) 明确提供多种高度、坡道、阶梯和 Godot 4.3+ 资源。允许商业游戏使用与修改，但禁止将原始素材、修改素材或模板另行上传分发；不应当作 MIT/CC0 开源素材直接纳入公开仓库。

## 3. 路线比较与建议

| 路线 | 实现方式 | 收益 | 主要工作 |
|---|---|---|---|
| A：纯 2D 等距 | TileMapLayer / Sprite2D，维护每格高度和投影 | 贴近手绘地图，复用当前 2D 管线 | 多高度遮挡、顶面拾取、悬崖面与单位排序 |
| B：3D 地形 + 2D 角色（优先验证） | GridMap 或模块网格 + 正交 Camera3D + Sprite3D | 高地侧面由几何产生，适合降低山脉绘制负担；可保留角色贴图与屏幕 UI | 地图节点、相机、拾取、高亮迁移；透明角色材质仍需处理 |
| C：逻辑 3D、显示 2D | 参考官方 Node25D 投影方案 | 兼顾高度坐标与 2D 图片 | 自定义投影/排序的维护，需验证复杂悬崖 |

推荐属于基于需求的工程判断：既然重点是块状高低地形与减少山脉手绘负担，应优先验证 B，而不是仅因当前是 2D 就排除 B。A 可作为固定镜头、手绘风格强约束下的对照。

## 4. 现有工程适配

- `godot-client/scripts/core/map_metrics.gd`：当前 48×48 直角坐标，直接乘除格宽；需要改为新的投影/空间坐标服务。
- `godot-client/scripts/core/map_loader.gd`：当前按 layout 写入 ground/structure/decor，没有读取每格 elevation；需扩充加载与显示映射。
- `godot-client/scripts/core/map_logic.gd`：客户端预览采用四邻接，注明后端是最终判定方。等距显示仍可保持四邻接；若高度影响通行，则客户端预览与后端规则都需同步。

建议先将高度与地形类型解耦：森林可以长在高地上，山地也可以有低洼入口。旧地图可默认高度 0。若仅为显示高度，可先做表现层原型；若加入爬升、跳落、高地射程或视线遮挡，必须扩展服务端数据和校验，不能只改客户端。

## 5. 草稿中需修正的判断

1. “3D 意味着所有 2D 角色、UI 全部重做”不成立。[SpriteBase3D](https://docs.godotengine.org/en/stable/classes/class_spritebase3d.html) 原生显示 2D 图片，并支持 billboard；UI 仍可屏幕叠加。需要重做的是空间挂载与相关交互，并非必然重画素材。
2. “按高度设置 z_index 即通用正确排序”不能成立。远处高地不能无条件盖住近处低地单位；简单高度图层不能保证所有遮挡。必须用前后排悬崖和低谷用例验证。
3. TileSet 自定义数据通常属于瓦片定义；同一瓦片被多个格子复用时，不能自然充当每格独立高度。每格高度应保存在地图数据/运行时格数据。[官方自定义数据说明](https://docs.godotengine.org/en/stable/tutorials/2d/using_tilesets.html#assigning-custom-metadata-to-the-tileset-s-tiles)
4. 2:1 菱形边线相对水平约 26.565°，不是 45°。美术等距与几何严格等距也应区分。
5. 本轮访问 OpenSword/OpenIsopix 返回 404，不能将其列为已确认可用的开源实现；不据此判断项目永久不存在。
6. “FFTA 没有高度差”、美术必然增加 3 倍、“3D 属于另一个项目量级”等草稿断言未获本轮可靠证据支持，不应作为决策依据。

## 6. 下一步验证

建议独立小场景比较 A/B：同一张小地图，包括三个高度、连续悬崖、坡道/阶梯、前后排单位、低谷，以及高地被遮挡时的选格。验收需要实际点击顶面、单位上下阶梯、正确显示移动范围、禁止跨越不可通行悬崖；截图正确不足以判通过。
