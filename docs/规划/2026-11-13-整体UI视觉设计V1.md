# BattleBlitz 整体 UI 视觉设计 V1

日期：2026-11-13。状态：已确认并实施；实际交付与验证范围见同日实施验收记录。本文保留前期视觉提案，以下补充覆盖原示意中的数值含义。

用户最终确认：底栏采用更高透明度，低矮全宽地貌置于中层，自屏幕底部长出；自然地貌两边高中间低，城镇可使用中央建筑主体。实现核查确认 MP 是游戏移动力，而非独立法力资源；底栏显示真实剩余移动力/移动能力，保留半点。不额外虚构 MP 资源。

## 1. 设计结构

```text
轻量军议风
├─ 统一规范：颜色 / 字号 / 间距 / 图标 / 交互状态
├─ 公共控件：按钮 / 页签 / 名牌 / 血条 / 列表 / 弹窗
├─ 叙事界面：标题 / 主菜单 / 剧情 / 结算
├─ 管理界面：备战 / 人物 / 装备 / 商店 / 存档 / 联机
└─ 战场界面
   ├─ 顶部：回合 / 阶段 / 资源 / 结束回合
   ├─ 中央：地图 / 选中反馈 / 就地行动菜单
   └─ 底部：单位概览 ↔ 战斗预测 ↔ 空地地形
```

箭头表示同一区域切换状态；页面复用控件，不强制建立继承体系。

## 2. 视觉语言

目标是让玩家先看清地图与数字，再感受到幻想军议氛围。装饰集中在标题、分隔线和地貌，不在每块区域反复叠加厚相框。

| 项目 | V1 提案 | 用途 |
|---|---|---|
| 阅读底 | 墨蓝 #111D2C | 底栏、列表和弹窗 |
| 次级底 | 灰蓝 #223247 | 选项、表头 |
| 主文字 | 象牙白 #F2EBDD | 名字、关键数字 |
| 次级文字 | 浅灰蓝 #AFBDCB | 说明与字段名 |
| 装饰 | 哑金 #B59B68 | 细分隔、选中标志 |
| 友军 | 蓝 #77BDEB | 阵营与范围 |
| 敌军 | 珊瑚红 #E48586 | 阵营与危险提示 |
| HP | 绿 #82BD99 | 血量，低血同时用文字/图形警示 |

上述为首轮设计候选，最终以实际背景上的对比度和截图为准。不得把候选颜色散落硬编码进各页面，接入时集中到主题配置。

以 1920×1080 为设计画布，间距采用 8 的倍数，细间距允许 4。标题约 32，区标题 24，正文 20，次级信息 18，HP 主数字 36；小窗口根据有效显示尺寸重排，不简单把整屏等比缩到无法阅读。

控件区分默认、悬停、按下、焦点、禁用、加载中。敌我不能只靠颜色；同时显示阵营名或图标。正文保持无衬线中文，装饰标题可使用项目许可范围内的标题字体。

## 3. 全界面布局

| 页面 | 布局 | 重点 |
|---|---|---|
| 标题/主菜单 | 左侧纵向菜单，右侧大幅环境画 | 继续游戏为最主要入口 |
| 主线章节 | 左章节列表，中地图/章节画，右任务摘要 | 显示解锁、进度和出击条件 |
| 出击准备 | 顶部功能页签，左队伍，中央人物，右能力与装备 | 下方固定出击按钮 |
| 人物详情 | 左立绘，右能力/装备/技能页签 | 强化 HP、职业与状态；次要说明可展开 |
| 商店/招募 | 左分类和列表，右物品或人物详情 | 金额、购买条件、确认结果明确 |
| 联机大厅 | 房间列表与筛选，右选中房间信息 | 建房/加入保持位置稳定 |
| 建房/房间 | 地图预览、规则、成员分区 | 准备状态与开始条件可见 |
| 存档 | 列表，右章节/队伍/时间摘要 | 读取、覆盖、删除清楚区分 |
| 设置 | 左分类，右控件，底部应用/返回 | 当前值可读，支持键盘焦点 |
| 剧情 | 大人物与场景，低位对话框 | 名牌、正文、继续提示有层级 |
| 战后 | 明确胜败标题，统计、成长、奖励分层 | 显示真实结果，退出路径清楚 |
| 地图编辑器 | 顶部工具，左素材，右属性，底部状态 | 与游戏共用视觉，保留工具所需密度 |
| 暂停/帮助/错误 | 适度遮罩与紧凑弹窗 | 一处主操作，明确可恢复路径 |

## 4. 底栏交互与数据

### 4.1 单位概览

首轮底栏约占画面高度的 20%～22%，地图相机使用扣除底栏后的可视区域。横向分配建议：人物约 24%，生命与资源约 24%，战斗数值约 22%，地貌约 30%；实际比例在长名字和最小窗口中复核。

- 人物：保留项目实际立绘；普通单位缺图时显示职业图标。裁切而非拉伸，头像不压住姓名。
- 生命：HP 当前/上限配血条；存在 MP 才显示 MP；移动力保留半点，不与 MP 混淆。
- 战斗：物攻、物防、魔攻、魔防、当前移动和基础射程。士气与状态作为独立标签。
- 地貌：背景展示该单位脚下地形的横向插画；字后加深色渐变，显示地形/地物名、高度、地形防御、对该单位有效的进入费用。

### 4.2 状态切换

| 输入/事件 | 底栏状态 |
|---|---|
| 选中友军或敌军 | 展示所选单位及实际脚下地形 |
| 浏览空地且没有锁定单位 | 地形视图，人物与战斗区收起或显示操作提示 |
| 单位锁定后鼠标掠过空地 | 保持所选单位信息，不抖动切换 |
| 确认移动目标前 | 明确标注“目标地形”，可同时保留出发地摘要 |
| 移动成功收到状态更新 | 切换到新脚下地形、剩余移动力 |
| 选择攻击目标 | 切换双方预测，给出伤害、反击、HP变化与本次高差收益 |
| 取消预测 | 恢复所选单位概览 |
| 单位死亡/退出/重开 | 清理失效选中状态，不保留旧数据 |
| 服务端预测未返回 | 显示计算中，不能展示上个目标的预测 |

高差攻击收益只能在具体目标确定后显示。无目标时只展示高度，不将条件收益写成常驻奖励。没有规则支持的回避、暴击等数值不因参考作品存在而加入。

### 4.3 工程边界

`main.gd`（管理主界面流程）只负责转交选中状态与操作；新增底栏组件负责显示；展示数据适配模块统一整理单位、地形与预测字段；`skin_assets.gd`（管理 UI 图片入口）集中载入地貌与控件素材。服务端继续负责正式结算。

不在每次鼠标移动时重新读磁盘或生成图片；相同背景复用缓存。未知地形使用中性背景，缺失数值显示“—”。地图旋转不旋转底栏背景插画，背景属于信息面板而非地图实体。

## 5. 素材生产与接入顺序

1. 概念稿：战场概览和全界面风格板，先确认视觉方向。
2. 可操作布局稿：使用真实中文字段、项目人物资源、长文本和小窗口验证排布。
3. 正式素材：地貌横幅、背景、边框、控件状态分层导出；不把文字或业务数字画进纹理。
4. 底栏接入：选中、移动、预测和实际战斗闭环验证。
5. 页面推广：入口与备战→人物与商店→大厅与存档→剧情、结算和编辑器。
6. 归档：中文变更记录、真实操作结果和截图；概念稿与测试截图分开保存。

本轮生成图是视觉提案，不能直接裁一整张当可交互界面，也不能当作实现完成证据。正式地貌种类以游戏数据枚举为准，避免为不存在的类型批量生产。

## 6. 概念稿记录

使用内置 imagegen，而非命令行 API。两项任务：

- 战场底栏概念：输入本项目历史战斗截图，移除左右厚边框，保留识别度，重排为顶部信息、中央地图、底部单位与地貌。
- 全界面风格板：主菜单、出击准备、人物详情、战斗预测四屏，使用同一墨蓝、暖白、细黄铜视觉语言。

图中示例数字、人物、地形效果用于版式讨论，不构成真实战斗规则或最终资产承诺。
