# Godot 截图驱动整改清单

日期：2026-07-29  
状态：实施前审查完成  
关联：[主线与战斗 UI 重做审计](2026-07-29-Godot主线与战斗UI重做审计.md)

## 使用方式

本清单来自三名独立审阅者对用户提供截图的审阅。每条均为可验收要求，不以“再调一点 offset”作为解决方式。实施团队必须在对应截图场景复现后逐条关闭。

## A. 主线存档页截图

涉及：`MainlineView/MLFrame/{MLListContainer,MLRightPlaceholder,MLBackBtn}`、`mainline_controller.gd::_render_mainline_slots/_build_slot_row/_render_slot_entry_hint`。

1. **重建左右列比例。** 左侧存档册占约 `38%`，右侧详情占约 `62%`；右侧不得只显示三行提示后留下超过其面积 `40%` 的无信息空区。
2. **区分选择和执行。** 单击存档卡只改变选中态；右侧展示章节、进度、更新时间、队伍/金币和下一步；唯一主按钮执行继续或新游戏。
3. **消除内部 ID。** `chapter_01_steel_rebellion` 等 ID 不得出现；展示章节 `title`、本地化摘要和进度，英文单词不得在卡内断裂。
4. **统一槽位层级。** 已占用槽显示“槽号 / 章节名 / 进度与时间”；空槽显示“空槽 / 从第一章开始”；不重复“第 1 章 / 新游戏”。
5. **收敛入口。** 选择主线槽页面若已承担继续、新游戏、删除/覆盖，就移除语义重复的“打开存档管理”；若保留跳转，必须有明确返回路径。
6. **正确使用资产。** 右侧详情可使用小型章节横幅、徽章、分隔线；`ChapterBanner` 不能是单纯低透明度背景，生成的边框不能整图拉伸。
7. **容器化实现。** 以 `MarginContainer + HBoxContainer` 管理列宽和底栏，避免 `MLFrame` 内固定 `offset` 随窗口漂移。

## B. 战前整备截图

涉及：`MLFrame`、`MLListContainer`、`MLPrepSelectorRow`、`MLPrep*` 节点，以及 `mainline_controller.gd::_render_mainline_prepare/_sync_prepare_selectors`。

1. **移除 prepare 的空左列。** prepare 模式不得复用清空后的 `MLListContainer`；必须显示 `Roster / Detail / Mission` 三栏，任意窗口都不出现无意义深蓝空列。
2. **删除全局五选择器行。** 当前最小宽度 `885px` 加间隔超出右栏可用宽度。每个 tab 只展示本页的 `1–2` 个选择器，或以栅格/换行容器处理；`1280px` 宽度绝不溢出。
3. **按 tab 控制交互。** 英雄页只显示英雄选择；装备页显示英雄和库存物品；佣兵/商店各自显示相关选择器。切换 tab 后保存当前焦点，不得保留无效控件。
4. **不再用 RichText 承载主要页面。** 英雄、部队、装备、佣兵、商店均使用原生卡片；装备流程清晰呈现“仓库物品 -> 目标槽 -> 确认”。
5. **展示层本地化。** 章节、职业、装备名称必须走 display mapper；禁止显示 `chapter_01_steel_rebellion`、`warlock`、`oak_staff`、`ruby_ring`。
6. **统一肖像语义。** 焦点肖像须由对应 `hero_id` 绑定，保持固定纵向裁切窗与原生边框；没有可靠肖像时使用职业剪影，不可用不对应角色的生成肖像。
7. **收敛底栏操作。** 固定底栏仅保留返回、保存/完成准备、开始战斗；tab 专属操作留在 tab 内容；放弃主线最右独立危险样式并二次确认。
8. **整合指挥官。** 指挥官放入右侧出征/编队情报；未完成时隐藏，不能漂浮在空白左下角。
9. **补齐任务摘要。** 右栏至少展示本地化章节名、当前战役、胜利/失败条件、敌方预览、推荐信息和奖励；不得只有裸数字。

## C. 战斗与对话截图

涉及：`GameView/HUD/{InfoPanel,HeroPortraitPanel,ActionBubble,DialogOverlay,DialogPanel}`、`main.gd` 对话/单位检视/行动菜单逻辑、`board_camera.gd`。

1. **无选中时没有空侧栏。** `InfoPanel` 默认 `visible=false`，相机不预留侧栏；开局棋盘中心占满安全区。
2. **检视内容合并为紧凑卡。** 单位详情、英雄缩略肖像和必要指挥官信息放入右侧 `<=320px` 的内容驱动卡；参战玩家列表移至战报或折叠区；普通单位不留头像空位。
3. **禁止大肖像层。** `HeroPortraitPanel` 不得占据左侧或整屏；`portrait_*.png` 只能进入 72–96px 裁切缩略窗，行动菜单不能覆盖其上。
4. **对话成为唯一 modal。** 对话开启时隐藏 `ActionBubble`、攻击确认和检视交互；遮罩拦截棋盘输入；继续/选择结束后恢复。
5. **修正对话选项容器。** 选项必须在 `DialogBody` 的右侧 VBox 中，与文本/头像同一流式布局，不能以绝对 offset 覆盖肖像或继续按钮；2–5 个选项均应可读。
6. **缩小并约束行动菜单。** 上下文菜单最大高度 `240px`，优先贴近单位，碰到屏幕/侧栏安全区时翻转；有 modal 时不显示。
7. **相机安全区按可见 HUD 计算。** 左/右检视卡显示时棋盘不被遮；dialogue 将棋盘作为背景而不是强制缩放；禁止使用固定百分比假设。
8. **显式层级与互斥。** Overlay > dialog > transient menu > normal HUD > board；同一时刻最多一个 modal，`Esc` 只关闭顶层。

## D. 实施顺序与验收

1. 主线实施组：接入 `MainlineCampaignPanel` 和 `MainlinePreparePanel`，移除旧空列/全局选择器，补 display mapper。
2. 战斗弹层组：重建 `DialogOverlay + DialogPanel + choices`，保证输入互斥。
3. 战斗检视组：缩小肖像与检视卡、收敛 ActionBubble、同步相机安全区。
4. 资产组：只接入 `assets/ui/rebuild/` 的九宫格边框和小图标；任何直接拉伸全屏/全栏资产均拒绝。

验收需要重新截取：存档页、整备英雄页、整备装备页、开局战斗、选中英雄、对话选项、行动菜单。所有截图分别在 `1280x720` 与 `1920x1080` 下确认无空列、溢出、遮挡、ID 泄露或不可操作区域。
