# Godot 主线与战斗 UI 重做审计

日期：2026-07-29  
状态：待确认后实施  
范围：主线存档入口、战前整备、装备页；战斗 HUD 仅处理布局基础设施，不改地图美术。

## 1. 结论

`bdede0e0` 的《Godot 主线与装备界面美术改造方案》与 `9fc2ab8` 的皮肤参考板方向正确：应以原生、可伸缩控件承载信息，以原创边框和图标作点缀。当前问题并非色板不足，而是后续实现偏离了这一前提：把概念大图作为运行时覆盖层，并在固定坐标的旧场景上继续叠加控件。

因此不应继续调整 `offset_*` 或添加更多装饰贴图。应保留主题 Token 与已验证的主线/存档流程，重建主线内容容器；战斗 HUD 另行容器化，避免再次遮挡棋盘。

> Git 拓扑更正：`bdede0e0` 是 `9fc2ab8` 的父提交，因此严格区间 `9fc2ab8..bdede0e0` 为空。本审计按两个端点及其后的运行时代码作比较。

## 2. 截图复现问题

### 2.1 主线存档页

- 左侧三存档槽可用，但右侧为大面积空白占位，未显示所选存档的章节、进度、队伍或下一步操作。
- 已占用槽向玩家暴露 `chapter_01_steel_rebellion` 这类内部 ID，且因换行破坏卡片可读性。
- “选择存档槽”的说明、空白面板和底部返回按钮没有形成明确的操作路径。

### 2.2 战前整备与英雄页

- 左侧约 40% 区域空置，没有方案要求的英雄名册。
- 右侧同时堆放摘要、标签页、五个全局下拉框、焦点卡和多组动作按钮；最后几个下拉框越出容器。
- 焦点卡能显示肖像/属性，但仍直接显示 `warlock`、`oak_staff`、`ruby_ring` 等内部 ID，且没有技能、经验、装备图标或本地化名称。
- “刷新整备 / 开始战斗 / 准备好了 / 刷新英雄 / 放弃主线”等操作重复并列，危险操作未物理隔离。

### 2.3 战斗 UI

- 现有 HUD 仍由固定像素面板拼接。`InfoPanel`、英雄肖像、对话框、战报和行动弹窗会争夺棋盘区域。
- 无选中单位时隐藏 `InfoPanel` 是正确修复；但选中后它仍是内容稀疏的全高侧栏。
- 棋盘相机仍含旧“左侧信息栏”可视区假设，而当前信息栏位于右侧，导致缩放和可视区计算不一致。
- 生成的边框/侧栏图若整张拉伸，必然出现角饰裁切、重叠和文本可读性下降。

## 4. 目标信息架构

### 4.1 存档入口：三栏战争档案桌

1. 左栏 `320px`：三个存档卡。卡片只显示本地化章节标题、进度、最近保存时间和一个主操作。
2. 中栏（弹性）：所选存档预览，包含章节横幅、剧情摘要、下一战目标和地图缩略图。
3. 右栏 `300px`：出征情报，包含队伍缩略、推荐等级、自动存档说明与主按钮。

空槽只显示“新游戏”，不保留巨型空白详情区。内部 ID 必须经过章节/职业/装备 catalog 映射后才可显示。

### 4.2 战前整备：军议桌

1. 左栏 `260px`：英雄名册卡，显示缩略肖像、纹章、等级、HP、装备数量和选中态。
2. 中栏（最小 `460px`，弹性）：焦点英雄或当前标签内容。
3. 右栏 `280px`：任务摘要，显示胜利条件、敌方预览、地图缩略图、资金与指挥官。
4. 底部固定行动条：返回章节、保存或刷新、唯一主操作“开始战斗”；放弃主线置于最右并使用危险样式。

标签页拥有各自的内容容器。禁止再使用一个全局 `MLPrepSelectorRow` 同时放英雄、装备、佣兵、商店五种下拉框。

### 4.3 装备页

1. 左侧：当前英雄肖像与基础属性。
2. 中间：武器、防具、饰品三张槽位卡，显示图标、本地化名称、加成与卸下动作。
3. 右侧：背包网格，显示库存、已占用、可装备、选中状态。
4. 底部：装备前后属性比较，使用绿/红/灰 Token。

### 4.4 战斗 HUD

1. 常驻 HUD 仅保留回合、当前阵营、金币、紧凑目标提示。
2. 选中单位时显示内容驱动的 `InspectCard`，最小宽度约 `300px`，不使用全高永久侧栏；英雄肖像嵌入该卡而非另占一列。
3. 对话、攻击确认、暂停、战报进入统一 `OverlayStack`。弹层出现时遮罩拦截棋盘输入，`Esc` 只关闭最顶层弹层。
4. 相机以实际 HUD 安全边距计算可视矩形；无选中单位时棋盘至少占可视区 80%，HUD 不覆盖中心 60%。

## 5. 技术实施方案

### 阶段 A：冻结基础设施

- 保留 `MainlineTheme` 与 `BattleTheme` 的颜色、按钮、文字、危险态 Token。
- 删除或禁用所有运行时 `ArtSkin` 大图覆盖逻辑；生成的 `battle_hud_frame_v1.png`、`battle_side_panel*.png`、`mainline_panel_skin_v1.png` 只能作角饰、图标参考或经过验证的九宫格来源。
- 新建 UI 截图基线：`1280x720`、`1920x1080`、窄窗口。

### 阶段 B：主线容器化

- 新建 `scenes/ui/mainline_campaign_panel.tscn` 和 `scripts/ui/mainline_campaign_panel.gd`。
- 新建 `scenes/ui/mainline_prepare_panel.tscn` 和 `scripts/ui/mainline_prepare_panel.gd`。
- 两者以 `MarginContainer`、`HBoxContainer`、`VBoxContainer`、`ScrollContainer`、`GridContainer` 实现；不再向 `MainlineView/MLFrame` 添加固定坐标子节点。
- `mainline_controller.gd` 只保留网络回调、状态切换与面板输入输出，不再拼装大段详情布局。

### 阶段 C：数据展示与本地化

- 新建 UI display mapper：章节 `title/summary`、职业显示名、装备 catalog `name`，禁止 UI 直接显示 `*_id`。
- 将英雄名册、任务摘要、装备槽、背包格做成独立可测试组件。
- 只在对应标签页实例化对应选择器；切页时回收其他页面控件。

### 阶段 D：战斗 HUD 基础重构

- 新建 `BattleHudLayout` 与 `OverlayStack`，拆分 `InfoPanel` 的指挥官、单位详情、参战玩家。
- 同步修改 `board_camera.gd` 的安全边距计算。
- 在布局稳定前不引入新的大边框图；仅使用原生 StyleBox 与小尺寸图标/角饰。

### 阶段 E：资产接入

- 仅在阶段 B-D 截图稳定后，将原创边框拆为真正的 `NinePatchRect` 或 `StyleBoxTexture`。
- 纹章、职业立绘、英雄肖像、地图缩略图可直接复用，但保持纵向肖像裁切与小尺寸点缀原则。

## 6. 验收标准

- 三个主线截图（存档、整备英雄、整备装备）在三种窗口尺寸均无裁切、重叠、选择器越界或大面积无信息空白。
- 玩家可见文案中不含 `mainline_id`、`class_id`、`equipment_id`。
- 存档选择、英雄切换、装备/卸下、准备完成和开始战斗全部通过真实后端流程测试。
- 战斗无选中单位时棋盘可用面积不小于 80%；对话或暂停时棋盘无法被操作，关闭弹层后恢复。
- Godot 解析、现有 `smoke_test.gd`、存档/主线流程测试通过；补充布局断言和三组截图人工验收。

## 7. 非目标

- 不重做后端主线、装备、存档规则。
- 不更换地图格或单位像素资产。
- 不复制外部游戏的 UI 图样、字体、人物或商标。
