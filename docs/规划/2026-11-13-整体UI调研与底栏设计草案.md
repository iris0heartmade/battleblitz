## 3. 视觉路线比较

以下均为本项目设计建议，不是参考作品的已核实特征。

| 路线 | 方向 | 收益 | 代价 |
|---|---|---|---|
| A 推荐 | 轻量军议风：墨蓝阅读底、暖白文字、细黄铜线、低饱和地貌插画 | 与既有人物和地图融合，保留辨识度，改善阅读空间 | 需要统一旧面板、边框和字号 |
| B | 浅纸战术图册：象牙纸、墨色标题、少量纹章 | 文字清爽，适合备战和列表 | 战场亮底与浅色地图需强化分层 |
| C | 剧场纹章风：深色舞台、大人物、大装饰 | 标题、剧情和结算表现强 | 常驻战场容易抢走地图注意力 |

建议 A 作为统一基础，标题/剧情允许 C 的表现力度。待参考画面分析后再定最终配色和材质。

## 4. 全界面结构

```text
统一视觉规范（颜色、字体、间距、焦点、状态、素材清单）
├─ 公共组件：按钮 / 页签 / 列表 / 数值 / 血条 / 提示 / 弹窗
├─ 游戏入口：标题 / 主菜单 / 设置 / 帮助
├─ 战前：主线章节 / 队伍 / 装备 / 商店 / 招募 / 出击准备
├─ 联机：大厅 / 建房 / 房间 / 队伍与指挥官
├─ 战场：顶部回合信息 / 底栏 / 行动菜单 / 战斗预测 / 日志
├─ 战后：胜败 / 战报 / 成长 / 奖励
├─ 内容：剧情对话 / 人物详情
└─ 工具：存档 / 地图编辑器
```

以上是组合与调用关系，不要求建立复杂的类继承。共享规范先统一，页面控制器继续负责各自业务。

## 5. 战场底栏

建议在 1920×1080 设计尺寸下以约 200～224 高作为首轮试排，最终以真实窗口截图验证。底栏占用正式布局空间，棋盘镜头与点击区域避开底栏。顶部仅保留回合、当前阵营、资源和结束回合。

```text
底栏
├─ 人物区：头像或裁切立绘 / 名称 / 职业 / 等级 / 阵营
├─ 生存区：HP 当前/上限 + 血条 / MP（有该资源才显示）/ 行动状态
├─ 战斗区：物攻 / 物防 / 魔攻 / 魔防 / 剩余移动力 / 基础射程
└─ 地貌区：脚下地貌插画 + 暗色阅读遮罩
   ├─ 地形名 / 地物名 / 高度
   ├─ 实际地形防御 / 此单位进入该格的移动费用
   └─ 条件提示：飞行、台阶、不可停留、设施效果
```

地貌背景跟随被查看单位实际脚下格子，不随鼠标偶然掠过另一格跳动。移动目标预览时显示“目标地形”标记，取消后恢复脚下格。空地只显示地形；敌方显示可公开的数值和阵营；无头像用职业图标占位。头像不拉伸，文字不烘焙进图片。

攻击预测进入底栏的独立对比状态：双方头像、HP 变化、预计伤害、反击与高差收益；同一位置稳定呈现，避免再叠两个相同信息面板。行动按钮保持靠近交互目标且不盖住底栏。

重要数值边界：地形防御是脚下格收益；高差攻击和射程依赖攻击者、目标、攻击类别与高度差，只在选定目标后显示实际值。未选择目标时不承诺“高地攻击 +2”。不新增本游戏没有的命中、回避等规则。

适配先覆盖 1280×720、1366×768、1920×1080；小窗口将次要数值收进详情，HP、单位名和地形保持可见。地图旋转、缩放后依旧不被底栏拦截或错选。

## 6. 数据与模块边界

现有 `main.gd` 的 `_refresh_unit_info`（控制单位详情刷新）同时负责布局、数值读取和富文本排版。建议在底栏改造时仅拆出相关职责，避免继续往主脚本堆逻辑。

- 展示数据适配层：从 GameState（通俗比喻：游戏最新账本）读取单位、地形和规则，生成底栏所需数据；不修改战斗结算。
- 底栏组件：只负责布局、头像、血条和文字，消费展示数据。
- 地貌资源清单：按地形、地物映射背景，未知类型使用中性背景；路径集中管理。
- 战斗预测适配：复用服务端结果，避免客户端自行重复推算最终伤害。
- 主题与素材入口：沿用现有主题模块和 skin_assets.gd，统一规范后替换资源。

现有单位详情用整数读取部分移动字段，新界面需核对“移动能力”和“剩余移动力”的字段口径，保留半点费用。飞行与台阶不能照抄固定地形费用。缺失数值显示“—”，真实零值才显示 0。

## 7. 素材与验收

先做一张包含长名字、普通单位、英雄、敌军与低 HP 的战斗样板，再批量生成。素材清单包括草地、岩地、沙地、水域等基础地貌和森林、道路、桥梁、城镇、城堡等地物组合；以项目实际地形枚举核对最终数量。背景采用横向构图，中心文字区域保持低细节。九宫格边框（通俗比喻：拉大面板时边角不变形的相框）和按钮状态单独导出。

验收必须在正式游戏完成：选中单位→移动到另一种地形→数值与地貌更新→选择不同高度目标→预测→实际攻击→HP 更新；继续检查飞行、半点移动、取消、无图、空格、已行动、切换回合、地图旋转、窗口变化。静态截图只能验证视觉，不能证明功能通过。
