# Godot UI 验收评分卡

基线：`71092d74`。本评分卡把 UI 改动的完成条件固定为可重复的自动化门槛和截图评审，不以“能启动”作为完成标准。

## 通过条件

1. Godot 烟测必须零失败。
2. `check_chinese_ui.py` 必须通过；扫描 `scenes/` 与 `scripts/` 里的 `text`、`placeholder_text`、
   `tooltip_text` 以及 OptionButton 的 `popup/item_N/text`。白名单仅限按键、协议和数值等不可本地化术语，
   不能屏蔽自然语言。
3. 在 1280×720、1600×900、1920×1080 三档中，截图工具每档均须生成完整的 11 张 PNG：
   主线存档、章节详情、新游戏整备、英雄页、装备页、战斗默认态、单位选中、
   行动菜单、对话框、暂停界面、战斗结算。
4. 每张截图按视觉层次、信息密度、操作引导、状态反馈、中文排版、整体一致性六项评估，单张平均不低于 8.5/10，所有截图总平均不低于 8.5/10。

## 窗格大小约束

以下数值是截图评审的客观参照（来源：`smoke_test.gd` 断言与 `board_camera.gd` / `main.gd` / `mainline_*_panel.gd` 常量），任一档分辨率下违反即判不合格。

| 窗格 | 约束 |
| --- | --- |
| 棋盘安全区 | 顶部状态栏保留 112px、底部 HUD 保留 16px；无检视卡时棋盘铺满安全区 |
| 棋盘右侧预留 | 检视卡显示时右侧预留 viewport 宽的 27%（相机把棋盘收进剩余 73%） |
| 单位检视卡（InfoPanel） | 宽 ≤ 460px，高 ≤ viewport 高的 84%，不得遮底部操作栏 |
| 行动菜单（ActionBubble） | 完整落在 viewport 内；内容距华丽边框底边 ≥ 12px；不得覆盖被选单位（72px 方块） |
| 席位卡（4P 大厅） | 最小高 ≥ 150px，标签不重叠、不压到创建按钮 |
| 英雄肖像 | 必须装进紧凑检视卡，不得溢出到面板外 |
| 响应式断点 | 物理窗口宽 ≤ 1366px 折叠左翼并补偿字号密度（密度系数 1.0–1.5）；>1366px 用完整布局（三档评审中 1280 为 compact，1600/1920 为完整） |
| 主线存档列 | 槽列 310–360px、情报列 310–336px（compact/normal），存档卡高 104–164px |
| 战前整备 | 面板最小 900×560px；英雄肖像框 118–144px；开始按钮 228–244px 宽 |

> 逐窗格的整改背景见 `docs/规划/主线/2026-07-29-Godot截图驱动整改清单.md`；本表是当前代码强制值，冲突时以本表为准。

## 主观评审引导提示词

条件 4 是主观题，为避免评审流于“看一眼给分”，给评审 agent（Codex）用下面这段提示词。它把评审从“打分”升级为“审视 UI 控件资产 → 定位缺陷 → 重新生成并复检”，让主观分有可执行产出物，而不是一句“还行”。

```text
你是 BattleBlitz Godot 客户端的 UI 资产验收评审员。你的任务不是“看一眼打个分”，
而是逐像素审视 UI 控件资产，发现缺陷就重新生成，直到达到验收线。

输入：
- 三档分辨率（1280×720 / 1600×900 / 1920×1080）各 11 张截图，共 33 张；
- 上一节“窗格大小约束”表作为硬性客观判据，违反即直接判不合格。

评审维度（每张截图逐项打分，1–10）：
1. 视觉层次：主次分明，操作权重最高，装饰不抢主内容；
2. 信息密度：无空列/无拥挤，右侧详情不留超过 40% 的无信息空区；
3. 操作引导：主按钮唯一清晰，可点击区域不溢出、不互相遮挡；
4. 状态反馈：选中/禁用/悬停/进度状态可见且互斥；
5. 中文排版：无英文残字、无后端 ID（chapter_01_…、warlock、oak_staff）、换行不破词；
6. 整体一致性：九宫格无整图拉伸、图标/字号/间距与主题一致。

UI 控件资产重点审视清单（发现即重做，不得只写备注）：
- 边框/面板：九宫格是否居中拉伸、四角是否走样、是否残留半透明边框；
- 按钮：三态（常态/悬停/按下）是否齐全、文字是否溢出、禁用态 alpha 是否一致；
- 名牌/徽章/牌匾：是否贴合背景、有无重叠徽记、是否被拉伸；
- 肖像框：是否为固定裁切窗、角色是否与 hero_id 一致、有无错位肖像；
- 标签页/选择器/列表行：选中态焦点环、行高、滚动是否裁切文字；
- 图标/分隔线：是否用错资产、是否被整图拉伸。

对每个发现缺陷的控件资产执行闭环：
1. 定位资产文件（assets/ui/…）或场景节点（scenes/ui/…）；
2. 用一句话描述像素级缺陷表现与触发分辨率；
3. 重新生成/修正该资产，并在三档分辨率下复检通过。

产出格式（JSON）：
{
  "screenshots": [
    {"name": "mainline_slots", "scores": {"视觉层次":9, "信息密度":8, "操作引导":9, "状态反馈":9, "中文排版":9, "整体一致性":8}, "total": 8.7,
     "asset_verdicts": [{"asset":"navy_gold_frame_9slice", "verdict":"重新生成", "reason":"右下角拉伸", "fixed":true}]}
  ],
  "avg": 8.85,
  "regenerated": ["navy_gold_frame_9slice"]
}

退出标准：每张截图单图平均 ≥ 8.5，33 张总平均 ≥ 8.5，且 regenerated 清单全部在
1280/1600/1920 三档复检通过；否则继续审视-重生成循环，不得以“已记录待办”结束。
```

## 运行须知

- 截图必须用 GPU 渲染而非 `--headless`：headless 模式无法读取 viewport 纹理，不能作为视觉验收依据。
- 跑卡前确认 `godot-client/project.godot` 没有未解决的 Git 合并冲突标记（`<<<<<<<` / `=======` / `>>>>>>>`）：
  冲突标记会让 Godot 报 `Error parsing project.godot`，导致烟测与截图全部无法启动。
- 无桌面/沙箱环境下 Godot 可能写不进 `user://`（`~/.local/share/godot`）而在启动时崩溃（signal 11）；
  可用 `XDG_DATA_HOME=<可写目录> "$GODOT_BIN" ...` 重定向 `user://` 后重跑。

```bash
GODOT_BIN=/path/to/Godot_v4.7-stable_linux.x86_64
"$GODOT_BIN" --headless --editor --path godot-client --quit
"$GODOT_BIN" --headless --path godot-client res://tools/smoke_test.tscn
python3 godot-client/tools/check_chinese_ui.py

for res in 1280x720 1600x900 1920x1080; do
  BB_REVIEW_RES="$res" "$GODOT_BIN" --rendering-method gl_compatibility \
    --resolution "$res" --path godot-client res://tools/ui_review_screenshot.tscn
done
```
