# 主线战斗布阵覆盖

> 适用于 `game/mainlines/*.json` 里的 `battles[*].spawn_overrides`。
> 当前约定：主线玩家 = `red` = 地图左侧；敌军 = `blue` = 地图右侧。

---

## 1. 职责边界

- `map.initial_units`
  - 地图默认出生表
  - 适合维护“这张图的标准左右开局”
- `battle.spawn_overrides`
  - 某一战斗对默认出生表的局部修改
  - 适合维护剧情战 / 守城战 / Boss 战差异
- `starting_units`
  - 英雄绑定、命名、可选精确绑位
  - 不负责批量定义敌我出生表

---

## 2. 应用顺序

运行时固定按下面顺序展开：

1. `remove`
2. `replace`
3. `add`

基底永远是地图文件里的 `initial_units`。

---

## 3. 字段格式

```json
{
  "spawn_overrides": {
    "remove": [
      { "color": "blue", "x": 12, "y": 9 }
    ],
    "replace": [
      {
        "match": { "color": "blue", "x": 12, "y": 8 },
        "unit":  { "type": "knight", "color": "blue", "level": 2 }
      }
    ],
    "add": [
      { "x": 11, "y": 9, "type": "healer", "color": "blue", "level": 1 }
    ]
  }
}
```

### `remove`

- 按 `(color, x, y)` 精确删除 1 个单位
- 找不到会在 mainline load 阶段直接报错

### `replace`

- `match` 按 `(color, x, y)` 精确匹配
- `unit` 是替换后的单位定义
- 如果 `unit` 不写 `x / y`，默认继承 `match.x / match.y`

### `add`

- 直接新增一个单位
- 必须显式写 `x / y / type / color`

---

## 4. 运行时校验

当前会做这些硬校验：

- `remove` / `replace.match` 必须命中已有单位
- 最终结果里不允许两个单位占同一坐标
- `teams` 里声明过的颜色，在 `spawn_overrides` 展开后仍必须至少有 1 个单位

也就是说，如果你把某一方最后一个单位全删掉，`load_mainline()` 会直接失败。

---

## 5. 推荐维护方式

推荐优先级：

1. 先把地图 `initial_units` 调成这张图的“标准左红右蓝”
2. 某一关只改差异时，再写 `spawn_overrides`
3. 英雄登场、名字、头像绑定，继续放在 `starting_units`

不建议：

- 在 `spawn_overrides` 里重写整张图全部单位
- 同时在 `starting_units` 和 `spawn_overrides` 改同一个设计问题
- 依赖“第几个单位”这种隐式顺序

---

## 6. 现成示例

当前仓库里的示例在：

- `game/mainlines/chapter_01_steel_rebellion.json`
- `battle_02.spawn_overrides`

这个示例演示了：

- 删除右侧 `blue healer`
- 把右侧 `blue warlock` 换成 `level 2 knight`
- 在更靠内的位置补 1 个 `blue healer`
