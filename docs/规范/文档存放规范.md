# BattleBlitz 文档存放规范

> **生效日期**:2026-07-21
> **约束级别**:项目级。所有 agent(人 / Claude Code / Gemini CLI / Codex / Copilot CLI / OpenSpace 等)均**必须**遵守。

## 1. 规则(强制)

1. **所有项目文档(`.md` / `.txt` / `.rst` / `.pptx` / `.docx` / 设计图)必须放在 `docs/` 目录树下。**
2. **禁止**在 `docs/` 之外的任何目录新建、改名、移动项目文档,包括但不限于:
   - 仓库根目录(只允许 `README.md` 入口)
   - `game/`、`godot-client/`、`tools/` 等代码子项目
   - 已经被 `.gitignore` 忽略的目录(`.tmp/`、`__pycache__/`、`venv/`、`node_modules/` 等)
3. 唯一例外:`README.md` 在仓库根与子项目根(`godot-client/README.md` 等),作为入口文件**可以保留**,但内容应是"指向 docs/ 的索引"而非"独立文档"。
4. 第三方参考仓库(`ref/`、`godot-client/ref/`)下的所有 `README.md` / `LICENSE` / `CHANGELOG.md` / `tips.txt` 等属于上游项目,不受本规范约束,不可修改。

## 2. docs/ 子目录分类(强制)

新增文档时按下面分类放,选最近的一个:

| 子目录 | 内容 | 命名样例 |
|---|---|---|
| `docs/架构/` | 稳定的设计文档(系统架构 + 分阶段开发方案) | `架构.md` / `阶段.md` |
| `docs/路线/` | 活的进度文档(路线图 + 项目状态快照 + 交接笔记 + **参考调研**) | `路线.md` / `项目状态.md` / `交接笔记.md` / `Godot移植方案.md` |
| `docs/路线/参考调研/` | Godot / 引擎 / 工具链的调研报告、对比表、插件清单、PPT | `2026-07-13-godot-高分红榜.md` |
| `docs/规范/` | 功能级 spec(地图生成 / 战斗音频 / 主线布阵 / 文档规范) | `地图JSON规范.md` / `主线战斗布阵覆盖.md` |
| `docs/规范/主线/` | 主线剧情文案、叙事弧、章节脚本 | `2026-07-21-叙事弧.md` |
| `docs/参考/` | 稳定的 how-to / API / 协议 / 模板 | `参考/llm-agent/api.md` |
| `docs/维护/` | 运维与质量(死代码 / 死资产 / debug 分析) | `死代码清单.md` / `2026-07-14-hero-mainline-debug-analysis.md` |
| `docs/维护/审计/` | 历次完整项目审计 | `2026-07-13-battleblitz-完整审计.md` |
| `docs/维护/死资产/` | 死代码 / 死资源 / 待删文件 | `2026-07-21-game-assets-unused-说明.md` |
| `docs/superpowers/specs/` | 历史 design spec 文档(已封档,只读) | `2026-06-30-victory-conditions-spec.md` |
| `docs/superpowers/plans/` | 历史 implementation plan 文档(已封档,只读) | `2026-07-21-complete-game-next-slices.md` |

## 3. 命名约定(强制)

- 文件名:**中文 kebab-case**。如 `战斗音频.md`、`2026-07-13-battleblitz-完整审计.md`。
- 子目录:中文短词(架构 / 路线 / 规范 / 参考 / 维护 / superpowers)。
- 日期前缀:`YYYY-MM-DD-` 用在调研报告、审计报告、superpowers 类文档。
- 文档间链接:**相对路径**,不要用绝对路径或 GitHub URL。

## 4. agent 必须遵守的工作流

每个 agent(无论人类 / AI)在以下动作时必须先读本规范:

| 触发动作 | 必读文档 |
|---|---|
| 新建 `.md` / `.txt` / `.docx` / `.pptx` 文档 | 本规范 + `docs/README.md` |
| 修改 README.md 内容 | 本规范 + `docs/README.md` |
| "我应该把这段说明写哪里?" | 本规范 §2 子目录分类表 |
| 重构 / 拆分子项目 | 本规范 + `docs/路线/项目状态.md`(避免破坏现有分类) |
| PR / commit 之前 | 跑 `git status` 确认无 `docs/` 之外的新增文档;若是,先把文件 `git mv` 到正确位置再 commit |

## 5. 如何贡献新文档

```text
1. 打开 docs/README.md,确认新文档应该归到哪个子目录
2. git mv / Write 到对应子目录(中文文件名)
3. 如果是新增子目录,先在 §2 表格登记
4. 在 docs/README.md "子目录导航" 表格里加一行
5. 在该子目录的 README.md(如果有)也补一行
6. commit message 写 "docs(<子目录>): <一句话摘要>"
```

## 6. 自检清单(commit 前必跑)

每次 commit 前在仓库根跑一次:

```bash
git status --short
# 检查点:
# 1. 没有 "?? " 标记且扩展名属于 (.md .txt .rst .docx .pptx .adoc) 的新文档在 docs/ 之外
# 2. 如果发现,先 git mv 到正确位置
# 3. 唯一允许的例外: 仓库根 README.md / godot-client/README.md / requirements*.txt
```

## 7. 违反规范的处理

- 由于本仓库不强制 CI hook(避免与各类 agent 工作流冲突),违反由 **人工 review** 兜底。
- 已在仓库历史里的 `docs/` 外文档视为 legacy,通过 07-21 D 任务一次性清理完毕,后续必须 0 容忍。
- 任何 review 中发现 `docs/` 外新增项目文档,**直接打回 commit**。
