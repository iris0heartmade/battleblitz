## 1. 入口与模块关系

```text
开始游戏.bat → project.godot → scenes/main.tscn
├── 主线 / 自由对战 / 联机 / 继续对局
│   ├── 原NetworkClient与GameState：请求、WebSocket、权威状态
│   ├── 原正式界面：移动、攻击预览、治疗、技能、招募、占领、回合、结算
│   └── scenes/board.tscn → Board（操作与三维舞台之间的接线板）
│       ├── 独立SubViewport：只绘制地图，菜单和HUD不随相机旋转
│       ├── board_model.gd：原始格子、建筑、阵营、单位 → 三维表现
│       ├── terrain_view.gd / map_contents.gd：高差地块、建筑、单位与拾取
│       ├── orbit_camera.gd：正交、环绕、平移、缩放与光标跟随
│       └── highlights_3d.gd / board_controls.gd：格顶高亮与输入
├── 正式地图编辑器 → 同一Board：地形、建筑、单位、高度、保存与撤销重做
└── 大厅选图预览 → MapPreviewSummary：同一份JSON生成二维部署缩略图
```

正式棋盘不再实例化旧TileMapLayer或Camera2D，不提供旧二维画面切换入口。旧像素资产与独立工具未批量删除；仍可能用于历史工具或非地图界面。独立Demo保留为材质与高度试验场，和正式客户端共享绘制代码、配置与材质。

双击“开始游戏.bat”通过共用启动器 `tools/run_godot.ps1 -FormalGame` 打开正式入口；自动寻找Godot、检查8000端口服务并验证高度字段。需要启动本机服务时，先通过SQLite备份API备份原数据库到 `game/.tmp/height-demo/backups/`，再运行原正式数据库；关闭客户端后只清理由该启动器启动的服务。已有兼容服务会直接复用，不结束其他进程。独立Demo仍用原快捷入口，使用不同数据文件。

所有运行时配置位于 `godot-client/scripts/board/height_map/`：`geometry.json` 管地块尺寸、高度比例、材质路径、镜头参数；`catalog.json` 管基础资源；`presentation.json` 管原地形映射、四方颜色、队伍色和地貌拾取高度。8张手绘材质已迁到 `godot-client/assets/terrain/handpainted/`。

## 2. 地形、地貌与单位

原逻辑格不旋转、不改变坐标。镜头默认水平45°、俯角30°，每格宽1世界单位，每级高差0.5世界单位。高度范围−5～+5，相邻允许10级落差。

- 未标高度的旧图：山地+3、雪峰+5、河流−1，其余0。明确存为0的山地仍为0。
- 地形顶面与可见柱侧按草、岩、沙、水分别呈现，保留原通行类型与防御属性。
- 地貌独立于高度：森林、城堡、村庄、佣兵站，以及城墙、门、台阶、金库、道路、桥梁有独立模型；单位落在当前格顶。
- 快照中的原始 `tiles` 直接传递，避免城堡子类型重新编码导致格子偏移；编辑器的一格一字符格式不会将相邻村庄或森林误读为城堡子类型。
- 红蓝绿黄四方及中立旗帜、独立队伍徽标、英雄立绘、等级、血量、移动力、士气、异常状态与已行动状态同步显示。占领进度与当前归属分开呈现，不提前改变旗帜所属。
- 后续快照更新保留单位根节点与动画当前位置，替换陈旧动画，避免刷状态时跳回原点或访问已释放对象。

大厅/战斗房间预览按用户要求恢复为二维俯视部署图，由同一份地图JSON生成，显示地形色块、建筑轮廓、各阵营总部与初始单位位置，不创建3D视口。地图说明与阵营摘要继续显示。随机地图明确提示“开局生成地形”，不画一张虚假的平原预览。正式战场和编辑器继续使用高差3D地图。

## 3. 操作、规则与兼容

游戏内：左键轻点选择或提交，左键/中键拖动平移，滚轮缩放，Q/E每次转45°，右键拖动改变朝向和俯角；右键轻点取消或查看单位射程。方向键与手柄继续控制逻辑光标，确认和取消复用正式动作流程。镜头遮挡与拾取保持一致，鼠标不穿透悬崖选择隐藏格；可以旋转相机，或通过逻辑光标访问。

只有“按下、松开且未超过拖动阈值”才提交点击；在界面控件上结束拖动也会清理按键状态。对话和模态面板期间，地图不提交动作。隐藏战场停止绘制，切回菜单不改动二维画布。

正式编辑器新增“高度绘制”：选择−5～+5后点击格子；也可方向键选格，空格或“应用到选中格”修改当前格。深坑底被挡住时，选中框透视显示，仍可用键盘或按钮编辑，不需要鼠标穿墙。高度修改纳入原撤销、重做与尺寸调整。

主线、自定义图、AI、联机、继续对局均沿用原会话和状态流程；没有改为Demo的同机双人流程。高差目前是表现数据，不增加爬坡消耗、坠落伤害或高低差射程规则。技能、招募、占领和胜负仍由原后端判断。

## 4. 地图高度协议

编辑地图JSON增加可选二维数组 `elevations`，排列为 `[y][x]`。缺省或空数组表示使用地形默认高度；提供时必须与地图宽高完全一致，且每项为严格整数−5～+5。布尔值、浮点数、数字字符串、尺寸不符及越界会返回422。

```json
{
  "size": {"width": 2, "height": 1},
  "layout": ["PM"],
  "elevations": [[-5, 5]]
}
```

上述仅展示字段关系；正式编辑器尺寸约束仍是15～45。自定义图保存后开局将高度写入每个Tile，状态接口返回可空 `elevation`。数据库启动迁移仅新增可空整数字段，旧格子保持NULL，由客户端取地形默认值；已有对局与中断快照缺少该字段也可显示。正式存档仍使用原流程，没有改写旧地图文件。

验证可通过 `BB_CUSTOM_MAP_DIR` 指向临时地图目录；缺省仍用原 `game/maps/custom/`。测试数据库与测试地图均与玩家数据隔离。
