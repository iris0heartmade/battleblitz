# 等距高差地图 Demo

日期：2026-11-10。本文记录独立Demo阶段。用户随后确认全面替换，正式客户端现状见[正式高差地图系统](正式高差地图系统.md)；本页后续“独立、不替换”等表述仅指历史Demo边界。

## 1. 边界与结构

```text
独立 Demo 场景
├── 地图模型：高度、地形、撤销重做、校验和存储
├── 地形渲染器：顶面、相邻落差侧面、射线选格、角色站位
├── 正交相机：45°水平转向、默认30°俯角、平移缩放和旋转
└── 编辑界面：高度、地形、基准网格、文件操作与状态
```

沿用 Godot 工程资源，入口为 `res://demos/height_map/main.tscn`；正式游戏入口与原地图保留。地图预览可离线运行，点击“开始试战”后连接独立后端，复用原移动、攻击、反击与回合规则。高差本身暂不参与战斗判定，仍由原地形类型决定通行成本和防御。

## 2. 地图与表现

默认进入15×15「2人标准图」，也可通过下拉菜单切回12×12高度试验场。每格水平边长1，高度为-5至+5的整数，一级0.5空间单位。相邻可直接相差10级，不自动平滑。配置在 `settings.json`，保存文件也记录尺寸和高度；加载严格校验，失败不改变当前地图。

0是测量基准，不放置覆盖负高度的实体地板。底座低于-5顶面。每格生成顶面，只在自身高于邻格时生成落差侧面；边界生成到底座的侧面。材质按世界尺寸重复，避免悬崖拉长。顶面及侧面使用新增手绘非像素材质，位于 `godot-client/demos/height_map/art/`；角色仍复用现有透明图片，通过Sprite3D展示。

### 局部近景与地形美术迭代

```text
表现地图
├── 相机：局部近景 → 面板右侧安全区 → 光标到边缘时平滑滚屏
├── 顶面：草地 / 板岩 / 沙地 / 水面四张手绘纹理
└── 侧面：根土 / 岩壁 / 沙岩 / 湿岩四张手绘纹理
    └── 上缘：按地形颜色收边，厚度由配置控制
```

默认镜头由19改为10.5，侧栏右侧作为可玩安全区，不再强求全图同时展示。初始镜头围绕角色光标取景，使用可配置的构图下移量减少上方空白。方向键允许按住连续选格，光标或升降后的地块靠近边缘时平滑跟随；手动平移取消未完成的跟随目标，避免松手回弹。比例、跟随速度、边距、平移阈值均在 `settings.json`。

8张新材质由内置image_gen生成，不替换旧地图资源；实际提示词见[素材生成记录](../参考/高差地图手绘材质生成记录.md)。采用线性过滤、各向异性与mipmap（通俗比喻：按远近切换清晰度，避免斜视纹理闪烁），去除最近邻像素过滤。各地形侧面独立配置，并加0.07空间单位的顶部收边。非水面顶面按格坐标确定旋转，降低重复纹理的整齐排列感；水面保持统一方向。水面侧壁为湿岩，不是透明水柱。

默认正交相机水平转向45°、俯角30°，与用户描述的斜俯视风格对应。左右按钮/Q、E每次平滑转动45°，右键拖动可自由360°环绕并调整俯角；连续转动跨360°不反向绕远。步长、平滑速度与拖动灵敏度由 `settings.json` 配置。选中描边跟随顶面高度，显示坐标和高度。基准网格可开关。

### 标准图移植：地形、地貌与单位分层

```text
原图 balanced_2p_15.json
└── 适配器：校验字符、保留原地形语义与坐标
    ├── 地形层：225格顶面与高度
    ├── 地貌层：2城堡 / 4村庄 / 2佣兵站 / 48森林格
    └── 单位层：红方5人、蓝方5人，固定在各自的原图坐标
```

原始文件为 `game/maps/balanced_2p_15.json`，为独立Demo打包复制到 `godot-client/demos/height_map/data/`。专项测试校验两份文本逐字一致；后续原图修改时需要同步这份资源。适配规则、建筑名称、阵营、单位图片与色板放在 `presentation.json`。不支持的字符明确报错，不自动伪装成草地。本轮适配范围仅为这张标准图的P/F/M/H/v/b，不声称全部旧地图已兼容。

原图没有每格高度，表现规则将山地M映射为+3，其他格为0；森林仍是草地底面，上放立体树木。这个高度是独立Demo的显示配置，不改变后端通行规则。建筑格保留 `source_terrain`，另记录 `feature` 和 `faction`；更换顶面材质、升降或撤销，不会删除建筑或驻军。

城堡采用带阵营旗的塔楼城寨，村庄采用成组屋舍，佣兵站采用帐篷、物资箱与旗杆。采用可旋转的代码原生3D模型，首版用于验证识别与布局，不冒充最终建筑美术。两座HQ依据原图注释的行优先顺序分配红蓝，村庄与佣兵站默认中立。

预设单位直接读取 `initial_units`，兵种、阵营、等级、坐标保持一致。本文件实际10个单位均为1级，未采用description中“1个Lv2”的旧说明。复用5种对应角色图片，红蓝底盘区分阵营。城堡与驻军的正常遮挡保留，可旋转或临时隐藏单位检查建筑；佣兵站驻军图片偏移到同格前沿，逻辑锚点仍位于原格。点击建筑或单位可选中其所在格，不需要穿过它们点击地面。

光标与预设单位分离：方向键只移动光标，不搬动单位；空格不会生成展示角色。沙盒仍保留单个随光标展示的角色。定位红方/蓝方按钮切到对应首个单位。X透视仅影响选中单位。新版存档版本2保存地貌、阵营和单位，兼容原版本1高度图，可跨12×12与15×15加载。

## 3. 操作与存储

启动：双击项目根目录 `高差地图Demo.bat`。启动器优先使用环境变量 `GODOT_EXE`，其次查找命令行的Godot与项目同级Godot安装目录；也可运行 `tools/run_height_demo.ps1 -GodotExe <Godot程序路径>`。默认自动启动独立试战服务，`-PreviewOnly` 可仅打开离线预览。

### 基础移动与战斗：同机双人首版

```text
3D场景与试战界面
└── BattleController：选人、模式、操作锁与反馈
    ├── BattleSession：独立HTTP会话，不污染正式客户端全局状态
    │   └── 原Python后端：创建双方 → 开局 → 移动 / 攻击 / 待机 / 结束回合
    ├── 移动范围：后端只读movement-options接口
    │   └── 原bfs_reachable / pathfind / 兵种地形规则
    └── 动画与显示：后端确认后走格、受击闪烁、生命、阵亡移除与结算
```

先支持红蓝同机双人轮流操作，不自动开启AI。选择主线模式的单位基础生成规则，以保留这张图原有的10人阵容与1级配置，不引入自由模式的HQ英雄替换；这不等于进入主线剧情。

操作：点击“开始试战”，点击当前阵营单位即可获得蓝色可移动格；点击目的地完成移动。点击“攻击”，再点红色范围内的敌人，先获取后端预计伤害、暴击伤害与反击预览，确认后真正提交攻击。点击“待机”结束该单位行动，“结束回合”交给另一阵营。Enter可确认光标所在格，Esc清除行动模式。生命数值来自权威快照，已行动单位变暗，阵亡后移除；胜负由后端决定。

鼠标左键在松开且未超过拖动阈值时才算点击，避免在蓝格上拖动画面时误提交移动。操作、动画与同步期间加锁，避免重复提交。移动动画沿后端预览路径逐格显示；最终落点、移动力、伤害与行动标记以操作后重新获取的状态为准。POST响应丢失时不盲目重发；同步失败则禁用战斗动作，允许“同步状态”恢复。

试战期间禁用地形编辑、地图切换和地图文件读写，防止地图显示与后端判定冲突。退出试战恢复进入前的编辑地图；试战会话保存在独立数据文件，但本轮没有加入继续对局界面。治疗等主动技能、占领、招募与AI尚未接入此Demo。

连接参数、回合模式和动画时长在 `battle.json`；可通过 `BB_HEIGHT_BATTLE_URL` 覆盖地址。默认服务为127.0.0.1:8766，独立数据库在 `game/.tmp/height-demo/battleblitz.db`，不会使用正式 `game/battleblitz.db`。启动器只停止自己启动的服务，不停止原来就存在的服务；关闭该启动器所属窗口后，自动清理自己的后台进程。已有服务需包含本轮movement-options接口，否则明确报错。

在Godot编辑器中，也可打开 `godot-client`，进入 `demos/height_map/main.tscn`，按F6运行当前场景。不要按F5启动旧游戏主入口。

默认存档实际位置可在点击保存后的状态文本查看；Windows通常位于 `%APPDATA%/Godot/app_userdata/BattleBlitz Godot Client/height_map_demo/map.json`。加载会替换当前Demo内容，修改后请先保存。自动验证只写 `height_map_demo/verification/`，不覆盖手动地图。

- 点击可见顶面选格；最近相交面如果是侧面则不选中后方地面。
- 每次升降1、直接输入、归零、撤销重做；地形可切换。
- 右键拖动旋转（左右改方位、上下改俯角20°～60°）；左键超过拖动阈值后、或中键、或Shift+右键拖动平移，滚轮缩放；按钮或Q/E左右旋转，复位恢复默认角度和比例并聚焦当前光标。
- 方位角和俯角实时显示；拖动旋转时俯角滑块同步，不触发反馈循环。高度输入时快捷键不转动镜头，文件对话框打开时不响应地图操作。
- 点击地图后方向键沿逻辑网格选格；F或“聚焦选格”使镜头对准该格；X或“透视选中”只改变选中框和展示角色的遮挡，不改变地形碰撞或鼠标防点穿规则。
- 预览模式中预设单位固定站位，角色显隐控制所有预设单位；高度试验场保留随光标展示的角色。开始试战后单位由后端控制，方向键仍只移动选择光标。
- 保存到独立 `user://height_map_demo/map.json`，先写临时文件再替换；支持加载、另存为/打开JSON；旧地图文件不受影响。
- 保存包含格式版本、尺寸、逐格高度和地形；相机比例由外部设置控制。载入后清空撤销历史，状态明确显示成功或失败。

## 4. 验收

数据测试：高度上下限、10级落差、撤销重做、非法文件拒绝、往返保存。标准图专项逐格核对225格、逐人核对10个单位；校验建筑数量、原文件一致性、跨尺寸/版本读档、未知字符与非法单位拒绝。场景测试：负高度、极限悬崖、侧面数、真实相机射线选格、建筑与驻军同步升降；隐藏单位同时关闭其拾取碰撞，避免空气墙；注入真实界面与地图点击。GPU截图检查红方、蓝方、村庄和全图。测试记录位于 `docs/测试/等距高差地图Demo验收.md`，仅记录实际执行结果。
