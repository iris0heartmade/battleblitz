# 主线-存档模型重构:对齐 FE8 的 per-slot 进度设计

> 状态:**提案 / 待评审**(设计文档,非立即执行)
> 创建:2026-07-23
> 背景:当前 `mainline_locked` 章节锁体验不好,根因是进度模型没对齐火纹(FE8 圣魔之光石)的「存档槽自带章节进度」设计。
> 参考:本地 FE8 反编译项目 `refs/fireemblem8u`(已通读 `bmsave.h` / `gamecontrol.c` / `worldmap_path.c` / `sram-layout.h`)

---

## 1. 问题:当前主线锁为什么难受

`_ensure_test_mainline_unlocked`(`routes/mainline/_common.py:160`)在进入非「当前允许章节」时抛 403 `mainline_locked`:

```python
# _common.py:117  只允许 chain 里"第一个没有通关存档的章节"
async def _current_mainline_for_user(session, user_name, chain):
    for mainline_id in chain:
        if not await _has_cleared_mainline(session, user_name, mainline_id):
            return mainline_id      # 唯一允许的章节
    return chain[-1]
```

后果:
- 玩家**不能回头重玩**已通关章节(FE8 允许!)
- 三个存档槽**不能各自停在不同章节**自由游玩
- 测试和真实流程都要绕开这个锁(见 `test_save_resume_fixes` 的适配)

---

## 2. FE8 怎么做:进度**长在存档槽里**,全局只存元数据

### 2.1 三个正式存档各自完整独立

`struct SaveBlocks`(SRAM 总布局,`sram-layout.h:82`)里 `gameSaveBlocks[3]` 物理上互不相交。每个 `GameSaveBlock`(`bmsave.h:350`)**自带完整进度**:

```c
struct GameSaveBlock {
    struct PlaySt       playSt;      // ★ chapterIndex(当前章节) + chapterModeIndex(分支线)
    GameSavePackedUnit  units[51];   // 整个 roster
    u16                 supplyItems[...];
    struct GMapSaveInfo wmStuff;     // ★ 本槽的世界地图:节点解锁位图 nodes[8]
    ...
};
```

- 章节位置 = `playSt.chapterIndex`(`types.h:179`)—— **每槽一份**
- 世界地图解锁 = `wmStuff.nodes[8]`(29 节点 × 2bit:VALID/CLEARED)—— **每槽一份**
- **没有全局"当前章节"**;`GlobalSaveInfo`(`bmsave.h:48`)只存元数据:通关记录、图鉴 `charKnownFlags`、`cleared_playthroughs[12]`、`last_game_save_id`(上次用哪槽)

> **三槽能各停不同章节是结构必然**:章节和世界地图状态是槽内字段。读档=载入某槽开玩,存档=写回该槽。没有全局游标 → 不需要任何章节锁。

### 2.2 章节推进靠事件脚本,不是线性数组

FE8 **没有** `if chapter==X: next=X+1`。下一章由剧情事件 `SetNextChapterId(id)`(`gamecontrol.c:722`)设定,状态机在 `GameControl_ChapterSwitch`(`gamecontrol.c:594`)执行:

```c
void GameControl_ChapterSwitch(struct GameCtrlProc* proc) {
    ...
    gPlaySt.chapterIndex = proc->nextChapter;   // ★ 下一章写进 PlaySt
}
```

好处:支持非线性(外传 Ch5x 插入、Eirika/Ephraim 分支)。

### 2.3 世界地图 = 章节入口,节点→章节双层映射

- 每个世界地图节点(`GMapNodeData`,`worldmap.h:334`)带 `chapteridx_eirika` / `chapteridx_ephram`;`WMLoc_GetChapterId(node)`(`worldmap_screen2.c:11`)按 `playSt.chapterModeIndex` 选分支。**同一节点对不同线跳不同章节**——分支靠数据不靠 if。
- 节点状态 `VALID`(可达) + `CLEARED`(已通关)(`worldmap.h:420`)。
- **已通关节点玩家可手动重玩**:世界地图 UI 不阻止光标落在 CLEARED 节点;`GetNextUnclearedChapter`(`worldmap_path.c:1901`)只把"未通关节点"当自动前进目标,但不禁止重玩。→ **这就是 FE8 允许回头、而我们却锁死的关键差异。**

进入章节流程:选节点 → `WMLoc_GetChapterId` → `StartBattleMap(chapterIndex)` → 章节结束事件 `SetNextChapterId(next)` → `GameControl_ChapterSwitch` 写回 → 回世界地图。

### 2.4 其它可借鉴点

- **Suspend(中断存档)2 槽轮替**(`bmsave.h:22-23`,写后翻转 `last_suspend_slot`)防掉电损坏。
- **多周目 `cleared_playthroughs[12]` 是全局表**,不参与存档槽选择,不污染 slot。

## 3. BattleBlitz 现状诊断:层级错位

好消息:`GameSaveSlot`(`save/models.py`)**已经很接近 FE8 的 GameSaveBlock**:

```python
slot_index      # 0/1/2 manual + auto — 对应 FE8 三槽
mainline_id     # 该存档在哪个主线
chapter_index   # 章节位置(== len(battles) 即通关)
snapshot        # JSON: roster/gold/active_mainline/mainline_progress(cursor)...
```

**问题:同时还有一个全局 live 游标**——`PlayerProfile.mainline_progress`(`engine.py` 直接读写的"活动进度")+ `active_mainline`。于是:

| | FE8 | BattleBlitz 现状 |
|---|---|---|
| 权威章节进度 | 存档槽内(`playSt.chapterIndex`) | **两处并存**:profile 全局游标 + GameSaveSlot |
| 世界地图解锁 | 存档槽内(`wmStuff.nodes`) | 无世界地图;章节锁按"有无通关存档"算 |
| 回头重玩已通关章节 | ✅ 允许 | ❌ 403 `mainline_locked` |
| 三槽停不同章节 | ✅ 结构必然 | ❌ 全局游标限制 |
| 章节推进 | 事件 `SetNextChapterId` 非线性 | `CAMPAIGN_CHAINS` 线性 tuple |

**根因**:该长在存档槽的"活动章节进度",被提升到了 `profile` 全局层,一个 user 只有一条线,才被迫加章节锁。**架构层级放错了。**

## 4. 改造方案:进度权威下沉到存档槽

### 4.1 核心原则(对齐 FE8)

1. **进度只认存档槽**:`GameSaveSlot`(已有 `mainline_id + chapter_index + snapshot`)成为唯一权威进度源。
2. **profile 只留元数据**(对齐 `GlobalSaveInfo`):解锁的指挥官/职业、图鉴、通关记录、`last_used_slot`。**移除 `mainline_progress` / `active_mainline` 作为权威**(可保留为"当前载入槽的缓存视图",但不参与判定)。
3. **删除章节锁** `_ensure_test_mainline_unlocked` + `_current_mainline_for_user`:每槽独立,无"回头污染"。
4. **"开始/继续"= 选槽载入**:从槽的 snapshot 恢复进度;**"推进章节"= 写回当前槽**,不写 profile 全局。

### 4.2 分阶段落地

| 阶段 | 内容 | 风险 |
|:--:|---|---|
| P1 | 引入"当前载入槽"概念:start/advance 读写**指定 slot** 而非 profile 全局游标 | 中(改 engine 写入路径) |
| P2 | 删除 `mainline_locked` 锁 + `_current_mainline_for_user`;放开重玩已通关章节 | 低(删逻辑 + 更新测试) |
| P3 | `profile.mainline_progress` 降级为缓存/移除,权威全部走 GameSaveSlot | 中(迁移现有存档) |
| P4(可选) | 引入世界地图节点模型:章节推进改事件驱动 `next_chapter_id`(非线性),支持分支/外传 | 高(新功能) |

> P1+P2 就能解决学长当下的痛点(回头重玩 + 三槽独立);P3 是彻底对齐;P4 是长期非线性主线能力。

### 4.3 数据迁移

- 现有 `profile.mainline_progress` → 为每个 user 的"当前进度"生成/更新一个 auto GameSaveSlot(已有 auto slot 概念)。
- `chapter_index >= len(battles)` 的语义保留(通关标记),但**不再用于锁定**,仅用于 UI 显示"已通关"和世界地图 CLEARED 位。

### 4.4 兼容与测试

- `test_save_resume_fixes` 里为绕锁改的 `chapter_test_02` 可回归为更自然的流程(删锁后 start 任意章节都合法)。
- 新增测试:三个 slot 分别停在 ch01/ch02/ch03,互不影响;重玩已通关章节返回 201。
