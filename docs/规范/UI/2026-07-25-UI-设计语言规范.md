# BattleBlitz UI 设计语言规范 (UI V3)

**作者:** 霞之丘诗羽(后辈:iris0heartmade)
**日期:** 2026-07-25
**适用范围:** Godot 4 客户端所有菜单/弹窗/HUD 子区域(不覆盖棋盘渲染)
**上一版:** UI V2(2026 早期 `menu_theme.gd` 初版)→ 本次升级到 V3

---

## 0. 动机

5 张截图修复之后,UI "能用了、不重叠"——但暴露了 5 类系统性问题:

1. **配色/字号散落在 151 处 `add_theme_*` 调用 + 91 处 inline `Color(...)`**,改主题需要逐处改
2. **没有网格系统**,按钮间距 12 / 24 / 60 / 108 各种值都有
3. **没有组件复用**,4 个 section(存档/主线/大厅/HUD 角落)各自手写 SectionHeader / ButtonRow
4. **空态 / 加载中 / 错误 三种状态用同色**,玩家分不清
5. **死区空白**(主线右半屏 600px 黑、存档右半屏 700px 黑)是布局层而非主题层的问题——本次只解决主题层,布局重排在 V4

V3 只做主题层收敛:**所有颜色 / 字号 / 间距 / 内边距必须走 token,不允许再 inline**。
V4(下一轮)再做布局重排。

## 1. 设计原则

| 原则 | 含义 |
|------|------|
| **8px baseline grid** | 所有 padding/margin/gap 是 8 的倍数(细间距允许 4) |
| **Token single source** | 颜色 / 字号 / 间距常量集中在 `MenuTheme`,其他文件禁止重复定义 |
| **Component over inline** | SectionCard / StatusBadge / ButtonRow 走 `_ui/` 公共组件,禁止 scene 里手拼 |
| **State-visible** | 每个控件必须能区分 default / hover / pressed / disabled / loading 五态 |
| **No scaling** | 立绘保持原图尺寸,panel 用 `clip_contents` 截溢出(规则在 V2 已立) |

## 2. 8px 网格

| 名称 | 值 | 用途 |
|------|----|------|
| `GRID_1` | 4px | 微间距(标签 ↔ 数值) |
| `GRID_2` | 8px | 紧凑间距(行内) |
| `GRID_3` | 16px | 标准间距(控件间) |
| `GRID_4` | 24px | section 内 padding |
| `GRID_5` | 32px | section 间 padding |
| `GRID_6` | 48px | 大块留白 |

**硬约束:** scene `.tscn` 文件里出现的 `offset_*` / `separation` / `content_margin_*` 必须命中上表之一,否则 code review 拒收。

## 6. 组件 API

所有组件放在 `godot-client/scripts/ui/_components/`,每个组件是一个 `class_name` + 静态构造器。

### 6.1 `SectionCard`(extends PanelContainer)

封装"section 标题 + body"通用容器。

```gdscript
class_name SectionCard

func _init(title: String, body: Control, hint: String = "") -> void:
    # 自动创建:
    #   - 顶部 14px 烫金小字 SectionHeader(title, hint)
    #   - 8px 间距
    #   - body(外部传入的 Control)
    #   - 16px 内边距的 Panel 容器,深绿底 + 烫金边
```

**使用模式:**

```gdscript
var card := SectionCard.new("三存档槽", slots_vbox, "按需手存,每槽独立")
add_child(card)
```

**契约:** title 必传;hint 可选(灰色小字附在 title 旁);body 可空(VBoxContainer fallback)。

### 6.2 `StatusBadge`(extends Label)

封装 ✓ / — / ⚠ / ⏳ 四种状态的视觉。

```gdscript
class_name StatusBadge

enum Kind { OK, EMPTY, WARNING, LOADING, ERROR }

func setup(kind: Kind, text: String) -> void:
    # 自动应用:
    #   - OK     → HEAL_GREEN 色 + ✓ 前缀
    #   - EMPTY  → TEXT_DIM 色 + — 前缀
    #   - WARNING→ FIRE_RED 色 + ⚠ 前缀
    #   - LOADING→ LOADING 色 + ⏳ 前缀 + 斜体
    #   - ERROR  → ERROR 色 + ✕ 前缀
```

**使用模式:**

```gdscript
badge.setup(StatusBadge.Kind.OK, "已选")
badge.setup(StatusBadge.Kind.LOADING, "指挥官 加载中...")
```

### 6.3 `ButtonRow`(extends HBoxContainer)

封装一行按钮 + 间距。

```gdscript
class_name ButtonRow

enum ButtonKind { PRIMARY, SECONDARY, DANGER }
func add_button(text: String, kind: ButtonKind = ButtonKind.SECONDARY) -> Button:
    # 自动用 MenuTheme 灌主题;PRIMARY=金底,DANGER=红边,其他=蓝底
    # 默认间距 16px;若只放一个按钮则右对齐
```

**使用模式:**

```gdscript
var row := ButtonRow.new()
row.add_button("继续", ButtonRow.ButtonKind.PRIMARY)
row.add_button("删除", ButtonRow.ButtonKind.DANGER)
row.add_button("覆盖", ButtonRow.ButtonKind.SECONDARY)
```

### 6.4 `SectionHeader`(extends Label)

V2 已经有 `MenuTheme.apply_section_header(lbl)`,但样式太弱。V3 升级为独立组件:

```gdscript
class_name SectionHeader

func _init(title: String, hint: String = "") -> void:
    # 14px 烫金 + 灰色 hint 副文
    # 下方 1px HSeparator 烫金
```

## 7. 迁移策略

### 7.1 不动的(已经在 V2 走 token)
- 所有 `MenuTheme.C_*` / `FS_*` 常量本身
- `MenuTheme.apply_button_theme` / `apply_panel_theme` / `apply_primary_button_theme` / `apply_secondary_button_theme`

### 7.2 必须改的

**优先级 P0(这次必须做):**

| 文件 | 改法 |
|------|------|
| `menu_theme.gd` | 补 GRID_* / C_LOADING / C_ERROR / C_PLACEHOLDER / FS_LOADING / FS_PLACEHOLDER token |
| `saves_controller.gd` | section header 改用 `SectionHeader`,按钮行改用 `ButtonRow`,空态用 `StatusBadge.Kind.LOADING/EMPTY` |
| `mainline_controller.gd` | 同上 + 章节列表行的状态文字 |
| `lobby` 相关(main.gd 里 `_build_lobby_seat_card` 等) | AI 替补/玩家/空 三态用 `StatusBadge.Kind`,按钮用 `ButtonRow` |
| `main.gd` 的 hero portrait panel 主题 | 改用 `apply_panel_theme` + 显式 GOLD 边 |

**优先级 P1(V4 再做):**
- 死区空白填 placeholder card(主线右半屏 / 存档右半屏)
- 按钮"覆盖 / 新建" 语义合并

## 8. 验证标准

跑完所有迁移后,4 张验证图必须满足:

1. **8px grid 一致**:相邻按钮间距、section 内 padding 都是 8/16/24/32 中之一
2. **配色 token 单一**:截图里出现的所有颜色都来自 `MenuTheme.C_*`,没有出现 `Color("#xxxxxx")` 写死
3. **状态可读**:`加载中…` 用 LOADING 色斜体、`空 — 可写入或被自动填充` 用 PLACEHOLDER 色 13px;玩家扫一眼就知道是"还在加载"还是"这里没东西"
4. **section header 统一**:所有"section title" 都是 14px 烫金 + 灰色 hint + 下方 1px 烫金分隔线(由 `SectionHeader` 组件保证)
5. **按钮主次分明**:`继续` PRIMARY(金底)、`删除` DANGER(红边)、`覆盖/新建` SECONDARY(蓝底)三态一眼区分

## 9. 不做的事(明确边界)

- **不重做布局**:死区空白、按钮分散等问题留到 V4
- **不引入新依赖**:仍用 Godot 4 内置 Control 节点,不开新 plugin
- **不改棋盘渲染**:棋盘 / 战斗 HUD 不在本次 scope
- **不写死像素**:viewport 1920×1080 不写死,组件用 anchor 适配
