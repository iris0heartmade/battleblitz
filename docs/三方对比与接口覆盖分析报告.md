## 0. TL;DR(三句话)

1. **后端已成平台**:13 个 FastAPI router + 2 条 WebSocket + 70+ 端点,所有裁决在服务端;客户端只发请求 + 渲染。
2. **Godot 客户端已接近替代 WebUI**:战斗回路 + 大厅 + 存档 + 主线 + 编辑器 + BGM + CO + WS 全部接好;只剩 Help 面板 / 手动存档按钮 / 服务器评论 UI / 部分 polish。
3. **真正未使用的接口**集中在 `progression/` 域(单位成长/转职/经验)、`profile/` 玩家档案的辅助端点、`commanders.py` 中几个非主流端点,这些主要是测试工具在用。

### 1.3 客户端架构哲学差异

- **WebUI**:**单文件 + 多视图**。`index.html` 一个文件里塞 13 个 `<section class="view" hidden>`,由 `showView(name)` 切显隐;所有逻辑在 `app.js` 7239 行;通过 `localStorage["battleblitz.session.v1"]` 保 session;手动实现的 DRAFT 滚动布局 + CSS Grid 自适应棋盘;`Dialog` 模块暴露 `window.dialog` 给 Playwright。
- **Godot**:**多 autoload + 信号驱动**。`Config → UserSettings → GameState → InputState → NetworkClient → AudioManager` 六 autoload 串行装载;`NetworkClient` 在 GameState 之后入树,通过 `_wire_to_game_state()` 反向接 WS 信号(规避 autoload-ordering trap,见 `MEMORY.md`)。`GameState` 暴露 20+ typed signals,`InputState` 维持 `mode: Mode{IDLE,UNIT_SELECTED,MOVE_MODE,ATTACK_MODE,CLAIM_MODE,RECRUIT_MODE,SKILL_MODE}`,所有视图都是 `main.tscn` 的子 Control,通过 `visible` 切换。`board.tscn` 被 GameView 和 EditorView 复用两次。

### 3.3 WebUI 覆盖度评估

唯一模板:`ws://<host>/ws/games/{game_id}?player_id=&since_seq=`(`network_client.gd:224`)。

## 10. 关键结论与建议

### 10.1 主要结论

1. **后端是稳定平台**:13 router + 70 端点 + 2 WS,前后端没有写业务冲突;`MEMORY.md` 的 `server-authority-no-duplicate-logic` 在两个客户端都贯彻(M2 的 MapLogic 是 UI 镜像,服务器仍权威)。
2. **Godot 客户端可作为主客户端**:战斗 / 大厅 / 存档 / 主线 / 编辑器 / BGM / CO / WS / 教程 / 战斗结算 / 暂停 / 截图工具都已落地;`docs/WebUI-vs-GodotClient-差异与计划.md` 列了 5 条 P1 缺口 + 4 条 P2 polish。
3. **真正未使用的接口**集中在:
   - `progression/*` 全部端点(单位成长体系尚无前端功能)— 主线"英雄转职/装备"经 `/mainlines/{id}/prepare/*` 间接到达,但 xp/promote 单卡没暴露
   - `profile/{name}/mainline/{start,advance,abandon}` 三个老路径(已被 `/mainlines/*` 取代)
   - WebUI 的 `prepare/complete` 与 Godot 的 `select-commander` 对调不均(Godot 没接到 UI)
4. **客户端未触发的"死代码"**:Godot 端 6+ 个 NetworkClient 方法已实现但 UI 未触发(详见 9.2)。

### 10.2 短期建议(可直接清理或接通的)

| 优先级 | 项 | 行动 |
|---|---|---|
| **P0** | Godot 接通 `/mainlines/{id}/prepare/complete` 触发("准备好了"按钮) | 在 `main.gd` 找一个合适 Tab 加按钮 |
| **P0** | Godot 加 `MainlineNextBtn` 触发 `next-battle` | BattleResultPanel 加 `mainline_next=true` 路径 |
| **P0** | WebUI 删除不需要的 `reach_tile/defend_turns` 表单 | 或更新为 seize 文档化 |
| **P1** | WebUI 通用编辑器补 "Delete Map" 按钮 | 一行 DELETE + 确认弹窗 |
| **P1** | Godot 加 Help 触发按钮 | 接通 main.tscn 节点 |
| **P1** | Godot 加静音切换按钮 | `_ready` 连线 |
| **P1** | Godot 加主菜单 `JoinByCodeButton` handler | 或干脆删节点 |
| **P1** | 后端 `/mainlines/{id}/select-commander` 暴露给 WebUI(已暴露给 Godot) | 检查 WebUI 是否调 |
| **P2** | Godot 实现 `commentary.text/audio` 渲染到战报 | 接 WS no-op 即可 |
| **P2** | 后端为 AI 评论加发送端点(聊天) | 等需求 |
| **P2** | 后端加 `progression/units/{id}/xp` 与 `promote` 的前端路由 | 主线准备页用 |
| **P2** | 清理 Godot `main.tscn` 重复节点 `EditorSurfaceOption` | 去重 |
| **P2** | 后端考虑引入登录/找回端点(或弃用 ensureProfile) | 看产品需求 |

### 10.3 总体策略建议

- **短期(2-4 周)**:Godot 客户端接好现成的死代码 + 接通 prepare/complete + 移除 disabled 节点
- **中期(1-3 月)**:Godot 完全替代 WebUI 作为主客户端,WebUI 冻结维护(只修 bug)
- **长期**:把主模式从"自由对局 / 主线 / 大厅"统一为"主线优先 + 大厅",PCU 模式(WebUI 当前主力)仅作为兼容入口
