# BattleBlitz 战斗音频约定

> 用途：记录当前 BGM 接入方式、配置边界，以及后续扩展成“可维护曲目表”的建议。

---

## 1. 当前实现

战斗 BGM 现在走统一的 `battle_config.audio.bgm` 结构。

- 自由建房：前端创建房间时只提交 `track_id`
- 主线战斗：`game/mainlines/*.json` 的 `BattleSpec.battle_config` 里只写 `track_id`
- 后端：读取 `game/config/battle_audio.json`，自动补齐 `loop / volume / fade_in_ms / fade_out_ms`
- 前端：拿到展开后的完整配置后，按 `/ui/assets/audio/bgm/<track_id>.mp3` 播放

这意味着：

- 用户不负责选择淡入淡出、音量等参数
- 主线和自由模式共用同一套音频协议
- 后续如果目录、后缀、播放实现变化，不需要改数据库或主线 JSON

---

## 2. 数据结构

最小输入：

```json
{
  "battle_config": {
    "audio": {
      "bgm": {
        "track_id": "sample_battle_01"
      }
    }
  }
}
```

后端展开后返回给前端的完整形态：

```json
{
  "battle_config": {
    "audio": {
      "bgm": {
        "track_id": "sample_battle_01",
        "loop": true,
        "volume": 0.8,
        "fade_in_ms": 1200,
        "fade_out_ms": 800
      }
    }
  }
}
```

字段约束：

- `track_id`
  规则：`[a-z0-9_-]{1,64}`
- `loop`
  当前默认 `true`
- `volume`
  范围 `0.0 ~ 1.0`
- `fade_in_ms` / `fade_out_ms`
  范围 `0 ~ 10000`

---

## 3. 文件位置

- 音频配置：`game/config/battle_audio.json`
- 前端静态资源目录：`game/app/web/assets/audio/bgm/`
- 当前示例文件：`sample_battle_01.mp3`

前端路径映射规则固定为：

```text
track_id = "sample_battle_01"
-> /ui/assets/audio/bgm/sample_battle_01.mp3
```

---

## 4. 当前职责划分

### 4.1 前端

前端只做两件事：

- 传 `track_id`
- 播放后端已经展开好的完整 BGM 配置

前端不负责：

- 维护默认音量
- 维护淡入淡出策略
- 按模式决定参数

### 4.2 后端

后端负责：

- 校验 `track_id`
- 从配置文件补全 BGM 默认参数
- 把最终配置持久化到 `Game.battle_config`

---

## 5. 未来扩展建议

当前 `battle_audio.json` 还是“默认值文件 + 少量 track override”。后续如果 BGM 数量变多，建议把它升级成“可维护曲目表”。

建议形态：

```json
{
  "bgm_defaults": {
    "loop": true,
    "volume": 0.8,
    "fade_in_ms": 1200,
    "fade_out_ms": 800
  },
  "tracks": {
    "sample_battle_01": {
      "title": "示例战斗曲 01",
      "category": "battle",
      "file": "sample_battle_01.mp3",
      "volume": 0.8,
      "fade_in_ms": 1200,
      "fade_out_ms": 800
    }
  }
}
```

建议新增但尚未实现的字段：

- `title`
  便于后台和内容编辑识别
- `category`
  如 `battle / boss / story / victory / defeat`
- `file`
  允许未来不再强依赖 `<track_id>.mp3` 命名
- `notes`
  记录曲目用途、关卡建议、循环点说明

---

## 6. 后续 agent 接手建议

如果后面要让别的 agent 继续做，建议按这个顺序推进：

1. 扩展 `game/config/battle_audio.json`
   目标：从“默认值文件”变成“曲目表”

2. 给后端加曲目注册校验
   目标：`track_id` 必须存在于配置文件，否则拒绝或降级

3. 给自由建房 UI 加曲目选择器
   目标：不要再手输 `track_id`

4. 给主线/模板编辑链路增加曲目元信息展示
   目标：内容编排时能看到 `title/category/notes`

5. 如有需要，再扩展多 cue
   例如：
   - `battle_bgm`
   - `victory_bgm`
   - `defeat_bgm`

当前阶段不建议做：

- 多轨混音
- 分阶段自动切歌
- 循环点编辑
- 浏览器内音频资源管理后台

---

## 7. 当前结论

现在的实现是一个刻意收敛的 0.x 版本：

- 协议已经统一
- 目录已经结构化
- 主线和自由模式都能接
- 参数已经从用户输入中收回到后端配置

它已经足够支撑 demo 和后续扩展，不需要立刻重构成更重的音频系统。
